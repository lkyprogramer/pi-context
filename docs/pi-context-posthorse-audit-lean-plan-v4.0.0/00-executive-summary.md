# 执行摘要

## 结论

本轮是实质改造：严格类型与打包恢复；认证用户的分支恢复更严格；读取分页、检索回声排除、FTS缓存、持久Lease、真实臂隔离和B2主比较已落地。上一轮“无法编译”“Lease仅Map”“主Gate仍比较B1”不应原样重开。

但目前不能得出“插件整体优于Pi Native”。最新300组运行 **289组四臂完整，11组中12个arm超时**；主两臂B0/B2实际完整290对。报告诚实保持 `keep-pi-native / publicationClaim=false`。它比旧版报告可靠，却仍有评分、指标和场景混杂。[S2]

**首要产品缺陷不是再缺一个记忆层，而是几个基本不变量没有满足：**

1. Reducer 已经提炼错误和关键输出，但默认组合根没有将 `reduced.visibleText` 回接 `visibleContent`。模型得到通用指针，不是提炼结果。完整日志在外存并不帮助模型及时了解刚完成的动作。[F01]
2. 当前叶子/lineage/模型既用于快照，又用作严格访问身份。消息自然前进后，前一叶子的证据被当前服务拒绝；不能通过简单去掉workspace/session条件修复，必须建立祖先可见性。[F02]
3. 活动尾部按role+normalized content去重。纯toolCall正规化为空数组，相同输出又发生合并；两个不同的工具步骤可被抹去。[F03]
4. 非text工具结果在入CAS前被清空，图片既不可见也不完整可恢复。[F04]

本次对原始模块进行了七组隔离探针，复现上述行为以及scorer的两类反例。没有运行完整Vitest或重新调用目标模型；隔离结果不替代真实宿主验收。

## 本轮后续范围：12个任务，3段验收

**段A（T01–T04）：** 修正旧认证fixture、稳定身份与祖先访问、观察返回、活动事件完整性。先证明“插件没有改变工具事实”。

**段B（T05–T11）：** 把计量、分页、评分、凭据隔离、少量真实工作区样例和产品开关连成同一条可测路径。多数任务可独立窄测；共享组合根顺序改，不并行碰同一文件。

**段C（T12）：** 一次集中本地全验收，再跑12个独立任务×2重复×2主臂，最多48个主臂运行；F0/B1只用于诊断失败。这个规模支持个人canary，不宣称统计证明2%非劣或行业最优。明确无收益即保留Native，不继续加层。

## 对此前设计的纠偏

此前方案把权限、快照和路由拼成同一Cursor，又过度追求广泛的发布门与证据治理。文档级合同并没有清楚说明“当前游标变化不应让祖先证据失去权限”。这些是规格不足，不能全部归咎于实现者。旧Task还大量使用通用步骤而未给出具体RED。本包改为来源可定位的具体反例、少量接口和真正可拒绝的验收。
