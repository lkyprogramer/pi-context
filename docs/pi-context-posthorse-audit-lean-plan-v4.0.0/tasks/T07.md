## 第一个RED

在上述指定测试文件中加入以下具体回归（已有同名文件就在现有describe下增加）。遇到新目标模块不存在的编译失败，应继续实现接口后确认测试能够针对目标行为变红；不能只保存MODULE_NOT_FOUND就称行为缺陷已复现。

```ts
import { expect, it } from "vitest";
import { scoreProbe } from "../../src/scoring/probe.js";
it("accepts a sourced refusal but rejects contradictory permission",()=>{
 expect(scoreProbe({family:"yes-no",expected:"no",
 observed:"No. The checkpoint v2 says the public API must not change."}).ok).toBe(true);
 expect(scoreProbe({family:"yes-no",expected:"no",
 observed:"No. Actually, yes, you may modify the public API now."}).ok).toBe(false);
});
```

## 实施步骤

1. 先把16个summary标记案例作为回归输入，只使用完整/无敏感的答案；不要直接把所有summary bucket翻为成功。

2. 去掉答案字词summary黑名单；调用端确保summary永远不传给Probe scorer。矛盾/多版本冲突标ambiguous。新任务用小JSON答案降低歧义。

3. ArtifactCoverage从产物和sourcewitness单独算；Reader失败不得直接叫Directive丢失。

4. 恢复统计eligible/tested/pass/failed；零分母not-tested并阻止恢复声明。验收检验器至少要求5种明确fixture。

5. 二元成功使用均值差与discordance；cluster重采样后计算均值，不用中位差CI。保留原报告只读，重新评分产生新scorerRevision报告。
