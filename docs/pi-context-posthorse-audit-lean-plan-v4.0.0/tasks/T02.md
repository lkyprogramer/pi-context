## 第一个RED

在上述指定测试文件中加入以下具体回归（已有同名文件就在现有describe下增加）。遇到新目标模块不存在的编译失败，应继续实现接口后确认测试能够针对目标行为变红；不能只保存MODULE_NOT_FOUND就称行为缺陷已复现。

```ts
import { expect, it } from "vitest";
import { buildBranchView, canReadSource } from "../../src/identity/branch-access.js";
it("reads ancestors but not sibling-only evidence", () => {
 const scope = {workspaceId:"w",sessionId:"s"};
 const entries = [{id:"r",parentId:null},{id:"a",parentId:"r"},
   {id:"b",parentId:"a"},{id:"sibling",parentId:"r"}];
 const view = buildBranchView(scope, entries, "b");
 expect(canReadSource(view,{...scope,entryId:"a"})).toBe(true);
 expect(canReadSource(view,{...scope,entryId:"sibling"})).toBe(false);
 expect(canReadSource(view,{...scope,sessionId:"other",entryId:"a"})).toBe(false);
});
```

## 实施步骤

1. 实现纯祖先计算：显式根、环检测、缺父拒绝；Entry ID由宿主ledger得到，模型不能提供授权证明。

2. Evidence新增sourceEntryId；tool/call/result在宿主提交后按callID+content hash幂等关联。prepared未关联记录不跨请求可见。

3. Repository由workspace/session+ID获取候选；canReadSource通过后，用record原cursor解密CAS。FTS必须先权限过滤再limit。

4. Owner键改为workspace/session；当前head/model成为传入view/fence，保存既有原始来源信息而非复制全部记录到每个新cursor。写队列按session稳定串行。

5. 默认context入口增量同步已提交宿主entries；scope不可识别时明确拒绝，不能退化成workspace全读。

6. 保留并复用当前authenticated fork继承；宿主可验证的子session来源关联与一般跨session读取分开。拒绝伪fork/缺父/重复ID，不扩大为跨会话搜索。

7. 新增真实Pi验收：写tool原文→追加用户/助手消息→回读；重启/模型切换仍可读；树兄弟不可读。
