## 第一个RED

在上述指定测试文件中加入以下具体回归（已有同名文件就在现有describe下增加）。遇到新目标模块不存在的编译失败，应继续实现接口后确认测试能够针对目标行为变红；不能只保存MODULE_NOT_FOUND就称行为缺陷已复现。

```ts
import { expect, it } from "vitest";
import { summarizeAttempts } from "../src/small-runner.js";
it("does not discard a product pair because a diagnostic arm failed",()=>{
 const rows=[{id:"s1",clusterId:"c1",repeat:0,
 B0:{status:"completed",success:true},B2:{status:"completed",success:true},
 B1:{status:"timeout",success:false}}] as const;
 const out=summarizeAttempts(rows);
 expect(out.primaryCompletePairs).toBe(1);
 expect(out.plannedPairs).toBe(1);
 expect(out.diagnosticFailures).toBe(1);
});
```

## 实施步骤

1. 新增summarizeAttempts目标签名在文件中显式定义：只对B0/B2计算primaryCompletePairs；可选B1/F0失败另列。

2. Preflight检查已有依赖/hostpatch、实际source-set hash、配置/模型/语料/scorer、凭据隔离标志；无PCR_LIVE不发请求。

3. 只运行两主臂，按repeat轮换顺序；独立workspace/HOME/Store拷贝，同一逻辑输入。冷/热缓存状态记录。

4. 每request保留完整usage/最终answer/stopReason/工具调用和环境断言，敏感字段脱敏；stream中断保留已知数据。

5. 一个results.jsonl+run.json+report.md+必要case证据；resume严格比较RunIdentity，不强制远端发布。

6. .source哈希覆盖实际代码/锁/运行器，不只wrapper；失败最终纳入分母，重试受同一限额，report=执行结果而非必须adopt。
