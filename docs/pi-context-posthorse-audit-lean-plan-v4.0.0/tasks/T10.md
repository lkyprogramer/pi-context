## 第一个RED

在上述指定测试文件中加入以下具体回归（已有同名文件就在现有describe下增加）。遇到新目标模块不存在的编译失败，应继续实现接口后确认测试能够针对目标行为变红；不能只保存MODULE_NOT_FOUND就称行为缺陷已复现。

```ts
import { expect, it } from "vitest";
import { createHash } from "node:crypto";
import { validateScenario } from "../src/small-runner.js";
it("rejects observed-state tasks without a real workspace",()=>{
 const text="A previous test process observed version=7.";
 const input={id:"x",clusterId:"c",provenance:"synthetic",mode:"coding",
  prompt:"Verify the current version from version.txt.",
  sourceEntries:[{id:"e1",role:"tool",text}],
  oracle:{kind:"observed-state",expected:"7",sourceEntryId:"e1",
    sourceSha256:createHash("sha256").update(text).digest("hex")},
  workspaceFiles:{},assertions:[{kind:"file-equals",path:"version.txt",expected:"7\n"}]};
 expect(()=>validateScenario(input)).toThrow("PCR_SCENARIO_STATE_UNWITNESSED");
 expect(()=>validateScenario({...input,workspaceFiles:{"version.txt":"7\n"}})).not.toThrow();
});
```

## 实施步骤

1. 提供validateScenario纯校验并绑定sourcewitness；question kind/expected/磁盘状态不能矛盾。

2. 把Reader-only目标题和Coding执行题分开；Coding每case自带最小项目文件、输入历史、目标任务、最终断言。

3. 环境断言由runner读取外置原始fixture生成；public API用已有TypeScript compiler API读取顶层export function节点，比较name/parameters，不能用注释中包含签名冒充未修改。测试和package.json必须哈希不变。至少三类完整例子：公开API不变修实现、先3后7的真实文件更新、日志中远处错误因果定位；同一模板变参标同cluster。

4. 回读验收必须生产tool观察→下一叶子→read原件；5种fixture即使不调用LLM也可验证。

5. 追加2个可本地复用的真实开发task时保留来源/去敏说明；缺独立真实holdout就不写real-independent。

## 边界测试（均为必需）

- expected没有sourcewitness拒绝
- requested-target不能标成已部署
- emptyworkspace观察题拒绝
- 重复cluster不扩独立样本数
- 断言本身先用故意错误代码验证会失败
- 禁止写测试直接把答案填到output

## 执行命令

```bash
pnpm exec vitest run packages/benchmark/test/small-corpus.test.ts
pnpm typecheck
```

命令使用目标仓库的已有pnpm环境；没有依赖时先安装冻结lockfile。T01创建的新统一命令仅供后续任务使用。实际模型命令只在T12显式授权后执行；其他任务用受控host或纯函数测试。

## 验收与失败处置

每case先手动/确定性确认Oracle可满足；反向mutation能使断言失败；样本总量和独立性分开报告。

修复后重跑同一RED与全部负例；保存命令、exit、失败原因和有效产物hash。任务可以因外部环境记blocked，但不得填passed。完成一个本地原子commit，不push。回归引入新失败时至多两轮定向修复，然后保存最小复现并继续其他ready任务。

**Reviewer重点：** 新结果是否来自真实产品调用点？是否仅把测试替身改成了期望答案？是否弱化权限/信息保留来满足性能？涉及Live的报告是否只更换了名称而没有观测相应能力？
