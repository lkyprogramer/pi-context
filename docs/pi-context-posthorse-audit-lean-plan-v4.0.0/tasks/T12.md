## 实施步骤

1. 先pnpm check:local，所有产品/pack红灯未解决则不启动Live；当前平台和目标平台结果分开记录。

2. 冻结source-set/hostpatch/model/corpus/config/scorer，任何变更另开run，不复用旧rows。

3. preflight无凭据泄漏/环境访问越界；PCR_LIVE=1且预算声明齐全才运行，缺条件记录blocked。

4. 最多12独立任务×2重复×2臂，按固定预算停止；F0/B1诊断另列且不影响主分母。

5. 用完整请求数据算task总token/时长，失败消耗也计入；报告artifact、reader、environment、recovery分别结论。

6. 两轮相同小实验仍无一致净值，终止复杂化并默认ingress；广泛优于Native的声明保持false。

## 边界测试（均为必需）

- 任何sourceepoch漂移不续跑
- 超时不从ITT删
- 价格未知不填0
- 安全失败立即终止后续arm
- 恢复n0不判pass
- 模型改变任务要求不得提高scorer

## 执行命令

```bash
pnpm check:local
pnpm eval:small -- --preflight
PCR_LIVE=1 pnpm eval:small -- --config experiments/personal-canary.json
```

命令使用目标仓库的已有pnpm环境；没有依赖时先安装冻结lockfile。T01创建的新统一命令仅供后续任务使用。实际模型命令只在T12显式授权后执行；其他任务用受控host或纯函数测试。

## 验收与失败处置

报告可以独立复算且明确“不足以统计证明2%非劣”；没有价值就保持Native；无需新的40Task计划才能结束。

修复后重跑同一RED与全部负例；保存命令、exit、失败原因和有效产物hash。任务可以因外部环境记blocked，但不得填passed。完成一个本地原子commit，不push。回归引入新失败时至多两轮定向修复，然后保存最小复现并继续其他ready任务。

**Reviewer重点：** 新结果是否来自真实产品调用点？是否仅把测试替身改成了期望答案？是否弱化权限/信息保留来满足性能？涉及Live的报告是否只更换了名称而没有观测相应能力？
