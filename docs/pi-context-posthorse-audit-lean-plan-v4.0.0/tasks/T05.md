## 第一个RED

在上述指定测试文件中加入以下具体回归（已有同名文件就在现有describe下增加）。遇到新目标模块不存在的编译失败，应继续实现接口后确认测试能够针对目标行为变红；不能只保存MODULE_NOT_FOUND就称行为缺陷已复现。

```ts
import { expect, it } from "vitest";
import { logicalInput, totalTaskUsage } from "../src/telemetry/request-usage.js";
it("does not confuse cache-exclusive input with context capacity",()=>{
 const u={requestId:"q1",sessionId:"s",phase:"continuation" as const,input:100,
 cacheRead:900,cacheWrite:0,output:20,inputSemantics:"exclusive-cache" as const,elapsedMs:10};
 expect(logicalInput(u)).toBe(1000);
 expect(logicalInput({...u,inputSemantics:"inclusive-cache"})).toBe(100);
 expect(logicalInput({...u,cacheRead:null})).toBeNull();
 expect(totalTaskUsage([u,{...u,requestId:"q2",input:50}]).logicalInput).toBe(1950);
});
```

## 实施步骤

1. 从响应完成事件将usage绑定发起时request/view，而不是新context读取全session最后assistant并归属新view。

2. 记录每次压缩、续跑、回读、重试；流式多次更新只覆盖同requestId的最终值。保留耗时与失败已知消耗。

3. 明确目标Provider适配器的input是否exclusivecache；不确定标unknown而不依赖字段名字猜。

4. I_eff用活跃Tools而非所有已注册Tools，包含system/图像/输出预留；未知overhead保守估算注明来源。

5. 金额仅按明确价格计算；免费本地环境也报告时间/请求数量，不冒充统一美元成本。

## 边界测试（均为必需）

- 相同requestId重复done不重复累计
- 模型/branch切换不引用旧响应usage
- unknown与0区别
- 缺输出token总输出null但known subtotal可见
- 未发出的请求不计算bill

## 验收与失败处置

两个请求的总计正确；cache不重复计或漏计；usage不能挂到另一个view；Provider trace有明确来源而不是全靠估算。

修复后重跑同一RED与全部负例；保存命令、exit、失败原因和有效产物hash。任务可以因外部环境记blocked，但不得填passed。完成一个本地原子commit，不push。回归引入新失败时至多两轮定向修复，然后保存最小复现并继续其他ready任务。
