## 第一个RED

在上述指定测试文件中加入以下具体回归（已有同名文件就在现有describe下增加）。遇到新目标模块不存在的编译失败，应继续实现接口后确认测试能够针对目标行为变红；不能只保存MODULE_NOT_FOUND就称行为缺陷已复现。

```ts
import { expect, it } from "vitest";
import { buildAgentEnvironment } from "../../scripts/credential-broker.mjs";
it("never passes a real provider key to tool subprocesses",()=>{
 const env=buildAgentEnvironment({PATH:"/usr/bin",HOME:"/tmp/fake",API_KEY:"SYNTHETIC_SECRET_123"},"/tmp/arm");
 expect(JSON.stringify(env)).not.toContain("SYNTHETIC_SECRET_123");
 expect(env.HOME).toBe("/tmp/arm");
});
```

## 实施步骤

1. buildAgentEnvironment父环境采用allowlist；不复制auth/models全文件，生成只含允许provider/model/loopback endpoint的配置。

2. 真实key只在Agent不可见的父进程/隔离外broker中，代理仅访问白名单目标model/route，并执行请求限额；不得暴露任意HTTP转发。

3. 明确环境清理不是sandbox：Agent进程文件系统不能读取宿主HOME与broker内存/进程环境，网络仅broker/fixture；无隔离证明则tools-enabled preflight阻断。

4. 无实际key的合成canary测试覆盖stdout/stderr/JSON/tar/索引，输出扫描结论只记录计数不打印secret。

5. 文档要求轮换已进入真实日志的key，旧原始证据本地只读限权；不得自动删除用户日志或推送密钥。
