## TDD第一条红测

将以下测试写入文件清单中的对应test文件，合并而非覆盖已有测试：

```ts
import { expect, test } from "vitest";
 import { HistoryIndex } from "../../src/history/index.js";
 import { user } from "../helpers/context-audit-fixture.js";
 test("duplicate rows do not consume insertion headroom", () => {
   const index=HistoryIndex.open({mode:"memory-only",dbPath:null,maxIndexBytes:150});
   const a=user("a",null,"x".repeat(100)),b=user("b","a","needle");
   const s={workspaceId:"w",sessionId:"s",leafId:"a",visibleEntryIds:new Set(["a"])};
   try {
     index.upsertBranchSync(s,[a]);
     index.upsertBranchSync({...s,leafId:"b",visibleEntryIds:new Set(["a","b"])},[a,b]);
     expect(index.status().rows).toBe(2);
     expect(index.status().bytes).toBe(106);
   } finally { index.closeSync(); }
 });
```

## 最小实施顺序

1. 按workspace/session/entry/block/hash身份先识别duplicate再比较预算；不能减计旧row后又新增两份。
2. 进程缓存已索引entry identities，只对增量计算字段hash；branch切换首次扫描IDs，已知对象不重复序列化大文本。数据源发生冲突Hash时显式source-changed，不覆盖原文事实。
3. persist=false的HOME/root按memory-only执行；SQLite不可用search=degraded，read仍按ref查Session。
4. 用构造1K/10K entries测无变化context、新增一项、branch切换的hashedFields次数；验收优先计数O(new)而不是开发机P95绝对时间。记录实际本机时间不放跨环境Unit硬门。
5. 文档写清logical index bytes和database physical bytes，quota不会删除canonical history；不加worker/后台vacuum架构。

## 负例与边界

- 配额正好相等可写，超一字节拒绝新条目但已有read可用。
- 重启、并发重复写按唯一键幂等。
- SQLite失败不能返回空命中+ok。
