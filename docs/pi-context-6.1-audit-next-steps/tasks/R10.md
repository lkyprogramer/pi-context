## TDD第一条红测

将以下测试写入文件清单中的对应test文件，合并而非覆盖已有测试：

```ts
import { expect, test } from "vitest";
 import { evaluateTrial } from "../../eval/local/gate.mjs";
 test("unexercised optimization cannot authorize a default change", () => {
   const d=evaluateTrial({pairs:[{caseId:"q",rep:0,nativePassed:true,candidatePassed:true,
     foldRequired:true,foldApplied:false,criticalViolation:false,evidencePassed:true}],
     capabilities:[],objective:{metric:"logical-input",known:true,relativeChange:-0.5,minImprovement:0.1}});
   expect(d.decision).toBe("inconclusive");
 });
```

运行：

```bash
pnpm check && pnpm build && pnpm smoke
```

新API未建立时的导入失败只是起始红测；实现最小API后必须确认断言在错误行为上失败，不能只保留“模块不存在”的红测记录。

## 最小实施顺序

1. 先check、build、stock packed smoke、安全canary。命令输出归档；遇到依赖/权限/Docker缺失BLOCKED，不换假Provider当live。
2. 运行testing/01-runbook.md的controlled lane，再以同tarball按预登记36episode预算运行live。不得调用用户未批准的外部模型、自动充值、无限retry或提高maxTokens。
3. 报告逐case成功与新失败、fold实际应用、错误/quote保留、检索循环、所有attempt成本和engine归因；小样本只能支持个人条件试用。
4. 若H02仍失败，按既有诊断链定位。没有證据表明Native摘要本身导致时不新增post-compaction-evidence-delta。
5. 更新README/HANDOFF准确列支持宿主、默认模式、实验身份与限制；旧报告保留日期与superseded说明，不删除失败记录。移除失效旧CI的宣称，不增加更多Gate平台。
6. 最终复验包在干净目录安装可用、observe字节透传和history成功；balanced结论不满足时保留off/observe默认产品，不把所有任务done等于效果赢。

## 负例与边界

- 少一个planned episode保持NOT_RUN；不做complete-case刷绿。
- 某目标模型没有cache价格时费用null仍可完成报告。
- 文档和report.json决策不同应失败。
