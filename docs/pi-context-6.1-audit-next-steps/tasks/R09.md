import { expect, test } from "vitest";
 import { validateScenario } from "../../eval/local/scenarios.mjs";
 test("oracle must have a real source and not be disclosed by the final prompt", () => {

## 最小实施顺序

1. 复用现有Java工程和trusted oracle；历史新增确定事实，最后prompt只指向任务，不给目标值、补丁方法或答案。每题包含反向oracle：初始坏代码失败、known-good通过。
2. 受控Pi路径先生产或导入同一合法JSONL seed，然后完整暴露目标工具观察，至少4个后续完整批次，达到相同预登记窗口60%后观察B2实际fold。未触发就是unexercised，不能给test虚构usage当作真实模型证据。
3. Q01-Q08两个arm冻结同seed/workspace/cut/预算；Native与candidate可采用不同记忆机制，但初始事实与环境相同。涉及native compact子集用相同源快照并记录两个实际host切点。
4. C01/C02能力题可以明确调用history，作为candidate-only诊断，不计B0失败提升成功率。质量题不强制专有工具；是否调用由模型自己决定。
5. source/initial-view/fold-before-after/native-summary/read/answer每环节只有Hash和许可诊断；定位H02丢失位置，再决定是否需要状态补充。
6. 将原L01-L06保留为no-fold交互回归但不每次执行真模型；H03生产窗口长压测保留为后续可选，不作为本轮自动预算消耗。

## 负例与边界

- 没有witness、oracle泄漏、仅复制fixture换ID、完整上下文Reader也失败都不得作为压缩损失。
- 同一个批次2个工具顺序颠倒/缺失有确定检测。
- 模型没回读但从保留摘要正确完成仍计成功，不能只奖励工具调用次数。
