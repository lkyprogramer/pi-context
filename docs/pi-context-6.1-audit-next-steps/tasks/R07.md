## TDD第一条红测

将以下测试写入文件清单中的对应test文件，合并而非覆盖已有测试：

```ts
import { expect, test } from "vitest";
 import { normalizeUsage, median, aggregateAttempts } from "../../eval/local/accounting.mjs";
 test("Pi already separated cache from input", () => {
   const u=normalizeUsage({input:100,cacheRead:60,cacheWrite:0,output:1},"pi-disjoint");
   expect(u.logicalInput).toBe(160);
   expect(u.freshInput).toBe(100);
   expect(u.cacheRatio).toBeCloseTo(0.375);
   expect(median([10,100])).toBe(55);
 });
 test("failed attempt usage is not erased", () => {
   const attempt=(id:string,status:string,input:number)=>({episodeId:"e",attemptId:id,status,
     requests:[{requestId:id+"-q",source:"pi-disjoint",usage:{input,cacheRead:0,cacheWrite:0,output:1}}]});
   const r=aggregateAttempts([attempt("a1","timeout",1000),attempt("a2","passed",10)]);
   expect(r.episodes.e.attemptCount).toBe(2);
   expect(r.episodes.e.logicalInput).toBe(1010);
   expect(r.episodes.e.firstStatus).toBe("timeout");
 });
```

## 最小实施顺序

1. 核对实际安装Pi适配器与raw SSE：记录映射版本；raw usage缺项与已知0分开。Pi.input不再减cacheRead，ratio使用logical分母。
2. message_end只记录assistant；native compactionEntry usage按purpose=compaction单列，后台transport重试从父Broker单独记；按requestId去重来源，不按输入Hash去重尝试。
3. run-matrix planned episode ID固定；每次attempt唯一追加到attempts.jsonl，result.json仅最终摘要不能覆盖ledger。blocked/timeout/aborted/empty结果全部保留。
4. 完整cost使用所有attempt并明确缺失。TTFT有send时间才叫TTFT；否则改名hookToFirstDelta。engine counter检查reset/model/exclusive污染，不能校正Pi逻辑量。
5. 将reference_metrics.py的JSON数值case移植为mjs测试；新增reasoning已含output、同请求多来源、失败无usage等负例。

## 负例与边界

- input40/cacheRead60合法，ratio.6。
- raw prompt10/cacheRead20返回invalid/unknown，不clamp成有效零。
- 缺少一次retry usage使totalunknown而非只报成功成本。
- 2次同内容请求各计一次，重复采集同request只计一次。
