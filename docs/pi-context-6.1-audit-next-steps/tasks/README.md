# 10任务主计划

**目标：** 在现有6.1单插件上修复已证实的运行/评测缺陷，让小型真实试验能够决定balanced是否值得。
**架构：** 官方Pi保留原生摘要；插件仅在ActiveView上折叠已确认暴露的旧纯文本工具结果。历史回读独立且有严格scope和分页。Parent broker隔离凭据。
**栈：** TypeScript、Node≥22.19、Pi0.85.1、SQLite、现有Docker与Python审计脚本。
**规格：** [目标设计](../design/00-target.md)、[测试协议](../testing/00-protocol.md)。不依赖外部Agent Skill。

优先：R01恢复有效CI；R02/R03修运行事实；R06安全可独立推进；R04/R05恢复和索引；R07/R08计量与判定；R09/R10集中场景和实验。不要因编号顺序让安全最后执行。

## AI执行边界

先写行为红测，再改实现，保存负例。定向测试+typecheck即可结束单任务；重型Host/Docker模型测试集中运行。共享plugin.ts的任务串行。文件清单是职责边界，不是为了通过形式门而禁止必要小修改：确需越界，在迭代记录说明原因并检查影响，不能擅自修改默认策略/Oracle。

每任务一次可审查commit，禁止`git add .`混入用户文件。使用实际改动文件列表。遇到BLOCKED写清缺失环境和已完成部分；不需要创建新task数据库或伪造Evidence JSON。任务测试的代码是需在目标仓库实现的规范，不意味着本ZIP已经修好产品。
