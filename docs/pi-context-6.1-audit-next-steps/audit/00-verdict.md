# 综合结论

**这次不是重做失败：产品已经显著变小，并修好了上一版的重要具体缺陷。保留6.1；不要重建Claim/Continuity/CAS/语义Worker体系。** 但“已经完成全部改动和测试”需要拆成：源码改造、真实宿主接线、效果验收，三者完成度不同。

当前建议：Native压缩继续默认，observe/history可作为受限个人使用；balanced仅用于显式调试。不要根据当前 `limited-balanced-trial` 自动推广。原因并非缺少一套更复杂的算法，而是其证明链仍有断点。

## 已经做对的部分

- 官方Pi0.85.1类型/安装目标；当前远端typecheck和packed检查通过。
- 不再抢占session_before_compact；不再自行写checkpoint、Pin胶囊或旧generation存储。
- 字段引用统一UTF8 hash；中文/emoji精确回读正控制成功。
- SQLite查询在生成excerpt前按workspace/session/visible ancestors过滤；同ID跨session负例已通过。
- 真实图片block返回；tool_result不再永久改写会话。新单插件路径和默认observe符合个人项目目标。
- 非联网判题容器、可信fixture和退出码成为实际判分条件，比旧宿主执行候选更好。

## 现在最主要的剩余问题

1. **活动请求和可回读历史被混用**：已经被Native摘要替代的旧工具正文仍参与折叠规划，产生“节省19865、实际替换0”的反例。原始历史应该可搜，但不能再被算成当前请求可节省量。
2. **成功暴露仅靠线性扫描推断**：兄弟分支成功响应、压缩后只读取摘要的响应都可能确认旧原文“已暴露”。需要一小段请求级内存见证，不需要复活旧持久化Ledger。
3. **分页函数正确不等于模型能翻页**：下一次工具调用推进leaf后cursor重置；模型可见content不含返回cursor；read游标还能串到另一字段。单页回读已修，多页流程未闭环。
4. **报告门宽于结论**：六个质量任务不折叠；质量每题少过一次仍允许通过；H02断言原文丢失不阻断；预填充增加40%也可通过“成本门”。合成反例只是验证评分器，不是说真实run发生了50%退化。
5. **凭据隔离回退**：Agent容器可读models.json中的真实API Key，bridge网络还允许额外外连；H03直接运行宿主。判题容器已改好，不能由此推断Agent也已隔离。

## 如何解释当前自报实验

日志声称37/37完成、L01–L06全部2/2、H01恢复通过、H02没有折叠isError条目；应承认这些窄信号。但H02同时记录balanced原文引用失败2/2，H03从未触发折叠；H01/H02 prefill比分别1.04和1.08是增加4%/8%，不是资源收益。不存在可供本轮独立复算的原始run归档。

继续优化的正确顺序：安全与当前请求正确性 → 分页与可恢复性 → 完整计量和Gate → 折叠后的真实任务 → 再决定是否改策略。暂不采用自动报告提出的 `post-compaction-evidence-delta`：还没有证明丢失发生于Native compact，而不是折叠、分页、模型没查询或回答要求不清。
