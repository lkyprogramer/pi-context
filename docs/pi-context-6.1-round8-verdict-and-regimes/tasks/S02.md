## 接口合同

**Consumes：** episode `requests[].normalized.freshInput/logicalInput/cachedRead`（R07 已产出）、`episode.wallMs`、`episode.engine.prefillTokensDelta`、`episode.mechanism.nativeCompactions`、`attempts.jsonl`、`manifest.plan.objective`。

**Produces：**

- `gate.mjs`：`metricOf(episode, metric): number | null`；`pairsFromItt` 为每个 pair 填 `nativeMetric/candidateMetric`（全部 `Metric`）；`objectiveFromPairs(pairs, planObjective): Objective`（纯函数，任一 pair 任一侧 null → `known:false`；`nativeSum === 0` → `known:false`）。
- `accounting.mjs`：`evaluateTrial(pairs, capabilities, objective, expectedPairs, expectedCapabilities)` 读 `objective.primary.{known,relativeChange,minImprovement,metric}`；`metric` 合法集合改为 `["fresh-input","logical-input","wall-time","monetary-cost"]`。
- `report.mjs` CLI：读取 `<runDir>/attempts.jsonl` 传入 `evaluateTrial({..., attempts})`；`objective` 由 `objectiveFromPairs` 计算，**不再**读 manifest 中的预置 `known/relativeChange`；`report.json.decision.objective` 输出完整 `Objective`（primary + secondary）。
- `run-matrix.mjs`：`manifest.plan.objective` 只写 `{ primary: { metric:"fresh-input", minImprovement:0.1 }, secondary:[...] }`，不写 `known/relativeChange`。
- `bundle.mjs`：`buildBundle` 把 pair 的 metric 与 attempts 摘要带入 bundle；`recomputeDecision` 用 `objectiveFromPairs` 复算，与 `report.json` 一致。
- `report.md`：新增 "## objective" 段，表格列出 primary 与每个 secondary 的 nativeSum / candidateSum / relativeChange / known。

## 非目标

不改门的通过/否决规则（S03）；不改 Q05/候选（S04）；不改 plan 的 rep 数（S03）。主目标固定 `fresh-input`、`minImprovement 0.1`，不得改为 `logical-input`。

## TDD 第一条红测

新建 `test/unit/objective.test.ts`：

```ts
import { expect, test } from "vitest";
import { objectiveFromPairs, metricOf } from "../../eval/local/gate.mjs";

const ep = (fresh: number[], cache: number[], wallMs: number) => ({
  wallMs,
  engine: { prefillTokensDelta: fresh.reduce((a, b) => a + b, 0) },
  mechanism: { nativeCompactions: 0 },
  requests: fresh.map((f, i) => ({ normalized: { freshInput: f, cachedRead: cache[i], logicalInput: f + cache[i] } })),
});

test("fresh-input objective is candidate over native minus one, pooled across pairs", () => {
  const pairs = [
    { caseId: "Q01", rep: 1, native: ep([45000, 200], [0, 45000], 40000), candidate: ep([11000, 150], [0, 11000], 30000) },
    { caseId: "Q01", rep: 2, native: ep([45000, 300], [0, 45000], 42000), candidate: ep([11000, 250], [0, 11000], 31000) },
  ].map((p) => ({ ...p, nativeMetric: allMetrics(p.native), candidateMetric: allMetrics(p.candidate) }));
  const o = objectiveFromPairs(pairs, { primary: { metric: "fresh-input", minImprovement: 0.1 }, secondary: ["logical-input", "wall-time"] });
  expect(o.primary.known).toBe(true);
  expect(o.primary.nativeSum).toBe(90500);
  expect(o.primary.candidateSum).toBe(22400);
  expect(o.primary.relativeChange).toBeCloseTo(22400 / 90500 - 1, 6);
  expect(o.secondary["wall-time"].relativeChange).toBeCloseTo(61000 / 82000 - 1, 6);
});

test("one unknown request makes the primary objective unknown, not zero", () => {
  const bad = ep([45000, 200], [0, 45000], 40000);
  bad.requests[1].normalized.freshInput = null as unknown as number;
  const pairs = [{ caseId: "Q01", rep: 1, nativeMetric: allMetrics(bad), candidateMetric: allMetrics(ep([11000], [0], 30000)) }];
  const o = objectiveFromPairs(pairs, { primary: { metric: "fresh-input", minImprovement: 0.1 }, secondary: [] });
  expect(o.primary.known).toBe(false);
  expect(o.primary.relativeChange).toBeNull();
});

function allMetrics(e: ReturnType<typeof ep>) {
  const out: Record<string, number | null> = {};
  for (const m of ["fresh-input", "logical-input", "wall-time", "cacheRead", "engine-prefill", "native-compactions", "requests"]) out[m] = metricOf(e, m);
  return out;
}
```

## 负例与边界

- `nativeSum === 0` → `known:false`。
- `requests.length === 0` 的 episode：fresh-input 为 `0` 但必须同时把 `requests` 指标记 0，且 report 的 flags 标 `no-requests`。
- `wall-time` 为 null 的 episode → 该指标 `known:false`，不影响主目标。
- `monetary-cost` 无 `pricingIdentity` → `known:false`，不得当 0。
- 同一 requestId 重复出现只计一次（沿用 R07 `aggregateAttempts` 语义；`metricOf` 以 `episode.requests` 为准，该数组已由 runner 去重）。
