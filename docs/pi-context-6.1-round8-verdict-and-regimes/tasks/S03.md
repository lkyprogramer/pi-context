## 接口合同

**Consumes：** S02 的 pair（含 `nativeQuote/candidateQuote`，本任务先允许为 null）、`plan.expectedPairs`、`plan.repsPerCase`。

**Produces：**

- `gate.mjs`：`discordance(pairs, exactQuoteIds): { b, c, shared, bByCase, discordant[] }`。
- `accounting.mjs`：`evaluateTrial` 按 §3 顺序；`review-needed` 的 reason 形如 `candidate new failures: Q05/r2 candidate-fail-native-pass; b=1 c=1 shared=0`；决策对象携带 `discordant`、`counts`。
- `scenarios.mjs`：`buildReviewPlan({ repsPerCase = 3 })` 输出 `schemaVersion: 2`、`repsPerCase`、`expectedPairs = qualityIds.length * repsPerCase`、`expectedCapabilities = capabilityIds.length * repsPerCase`、`plannedEpisodes = expectedPairs*2 + expectedCapabilities`（本任务不含 W/X，S06 再加）；`order[].lane` 与 `kind`。
- `review-spec.mjs`：`REVIEW_BUDGET.run = { totalWallMs: 7_200_000, totalModelCalls: 1_500, totalToolCalls: 2_400 }`；episode 预算不变。
- `review-matrix.json`：由 `buildReviewPlan()` 重新生成（`node -e` 一次性脚本，不提交脚本），48+6 = 54 episode 全 `UNRUN`。
- `report.md`："## decision" 段由 `renderDecision(decision)` 生成：decision、reason、discordant 列表、counts、attemptRates、objective.primary 一行。

## 非目标

不改 oracle；不改折叠参数；不加 W/X lane（S06）；不把 `shared` 失败算作候选退化；不引入统计显著性检验之外的"平滑"。

## TDD 第一条红测

追加到 `test/unit/trial-gate.test.ts`：

```ts
import { evaluateTrial } from "../../eval/local/gate.mjs";

const pair = (caseId: string, rep: number, n: boolean, c: boolean) => ({
  caseId, rep, lane: "Q", nativePassed: n, candidatePassed: c, nativeQuote: null, candidateQuote: null,
  foldRequired: true, foldApplied: true, criticalViolation: false, status: "complete",
  nativeMetric: { "fresh-input": 45000 }, candidateMetric: { "fresh-input": 11000 },
});
const plan = { expectedPairs: 24, expectedCapabilities: 6, exactQuoteIds: [], objective: { primary: { metric: "fresh-input", minImprovement: 0.1 }, secondary: [] } };
const caps = Array.from({ length: 6 }, (_, i) => ({ caseId: i < 3 ? "C01" : "C02", rep: (i % 3) + 1, eligible: true, passed: true }));

test("one discordant pair with an offsetting discordant pair is not review-needed", () => {
  const pairs: ReturnType<typeof pair>[] = [];
  for (const q of ["Q01","Q02","Q03","Q04","Q05","Q06","Q07","Q08"]) for (let r = 1; r <= 3; r++) pairs.push(pair(q, r, true, true));
  pairs[12] = pair("Q05", 1, false, true);   // native fails, candidate passes
  pairs[13] = pair("Q05", 2, true, false);   // candidate fails, native passes
  const d = evaluateTrial({ pairs, capabilities: caps, plan, attempts: [] });
  expect(d.decision).not.toBe("review-needed");
  expect(d.discordant).toEqual(expect.arrayContaining([
    expect.objectContaining({ caseId: "Q05", rep: 2, kind: "candidate-fail-native-pass" }),
  ]));
  expect(d.counts).toMatchObject({ b: 1, c: 1, shared: 0 });
});

test("two candidate-only failures on one case are review-needed with the pairs named", () => {
  const pairs: ReturnType<typeof pair>[] = [];
  for (const q of ["Q01","Q02","Q03","Q04","Q05","Q06","Q07","Q08"]) for (let r = 1; r <= 3; r++) pairs.push(pair(q, r, true, true));
  pairs[12] = pair("Q05", 1, true, false);
  pairs[13] = pair("Q05", 2, true, false);
  const d = evaluateTrial({ pairs, capabilities: caps, plan, attempts: [] });
  expect(d.decision).toBe("review-needed");
  expect(d.reason).toContain("Q05/r1");
  expect(d.reason).toContain("Q05/r2");
});
```

运行：

```bash
pnpm exec vitest run test/unit/trial-gate.test.ts --config vitest.config.ts
```

当前 `evaluateTrial` 对第一条返回 `review-needed`（任一 candidate 失败），第二条 reason 不含 pair → 两条都是有效红测。

## 最小实施顺序

1. `gate.mjs` 增加 `discordance`；`evaluateTrial` 输入对象增加 `plan`，从中取 `expectedPairs/expectedCapabilities/exactQuoteIds/objective`（保持旧位置参数可选以免破坏 bundle 复算，或同步改 `bundle.mjs` 调用）。
2. `accounting.mjs` 重写 `evaluateTrial` 的第 5 步；保留第 1–4、6–8 步语义；`quality-qualified-cost-unknown`、`history-only`、`limited-balanced-trial` 分支读 `objective.primary`。
3. 现有 `trial-gate.test.ts` 用例逐条核对：
   - "one loss per two repetitions is not a passing quality gate"（12 pair，每题只过 1 次）：新规则下 `bByCase` 每题 1、`b=6, c=0` → `b−c ≥ 2` → `review-needed`，仍不得 `limited`。保留。
   - "H02 quote failure is review-needed"：改为 `exactQuoteIds: ["H02"]`、candidate quote false / native quote true → `quote-discordant` 计入 `b`。
   - "unexercised optimization cannot authorize a default change"、"no fold cannot enter…"、"unknown cost…"、"missing planned pair…"、"critical violation is blocked"、"zero recovery opportunities…"：输入改用 `plan`，期望不变。
   - "first-attempt and final success rates are separate"：传 `attempts`，期望不变。
4. `scenarios.mjs`：`buildReviewPlan({ repsPerCase })`；更新 `review-scenarios.test.ts` "frozen review plan is 32 quality + 4 capability" → 48 + 6；`review-live-wiring.test.ts` "ITT matches frozen review episode ids" 用新 plan。
5. 重新生成 `eval/local/review-matrix.json`；`review-spec.mjs` 预算。
6. `report.mjs`：`renderDecision`；删除或改名旧 `decideGates/decide`（若删除，`test/unit/` 中引用 `decide` 的测试一并调整为 `evaluateTrial`）。

## 负例与边界

- `b − c ≥ 2` 但分散在不同 case（各 1 次）→ 仍 `review-needed`（总量规则）。
- 所有 pair 双败某 case 3 次 → 不进 `b`，`shared=3`，report flags `task-noise: Q0x`，决策继续往下走。
- `nativePassed == null` 任一 → `inconclusive`，先于不一致统计。
- `expectedPairs` 与 plan 不符 → `inconclusive`。
- reason 字符串长度上限 2000 字符，超出时截断并附 `+N more`，`discordant` 数组保持完整。
