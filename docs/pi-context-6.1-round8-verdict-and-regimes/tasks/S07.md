## TDD 第一条红测

新建 `test/unit/docs-decision-consistency.test.ts`：

```ts
import { existsSync, readFileSync } from "node:fs";
import { join } from "node:path";
import { expect, test } from "vitest";

const repo = join(import.meta.dirname, "../..");
const ENUM = ["blocked", "inconclusive", "review-needed", "quality-qualified-cost-unknown", "history-only", "limited-balanced-trial"];

test("delivery docs quote the same decision as review-final/report.json", (ctx) => {
  const p = join(repo, "artifacts/local-eval/review-final/report.json");
  if (!existsSync(p)) { console.log("BLOCKED: review-final/report.json missing"); ctx.skip(); }
  const report = JSON.parse(readFileSync(p, "utf8"));
  const decision: string = report.decision.decision;
  const runId: string = report.manifest.runId;
  expect(ENUM).toContain(decision);
  expect(report.manifest.diagnosticOnly ?? false).toBe(false);
  for (const f of ["README.md", "HANDOFF.md", "docs/OPERATIONS.md", "docs/CONFIGURATION.md"]) {
    const text = readFileSync(join(repo, f), "utf8");
    const m = text.match(/(?:交付决策|delivery decision)[^\n`]*`([a-z-]+)`/);
    expect(m, `${f} must state the delivery decision`).toBeTruthy();
    expect(m![1], f).toBe(decision);
    expect(text, `${f} must reference the run id`).toContain(runId);
  }
});
```

运行：

```bash
pnpm exec vitest run test/unit/docs-decision-consistency.test.ts --config vitest.config.ts
```

当前 `review-final/report.json` 存在（第 7 轮 `inconclusive`）而 README 用 "delivery ... is **`inconclusive`**" 句式：正则可能匹配也可能不匹配；无论哪种，`runId` 断言（当前文档未写 `review-final` 的 runId）会失败 → 有效红测。若正则对现有句式不匹配，调整正则而不是文档，直到红测只因 runId/decision 不一致而失败。

## 允许的结论与措辞

- `limited-balanced-trial`：写"个人显式试用；默认仍 observe；无非劣性声明"。
- `history-only`：写"折叠无预登记净收益；保留 observe/history"。
- `review-needed` / `quality-qualified-cost-unknown` / `inconclusive` / `blocked`：照 reason 原文，不解释为"接近通过"。
- 任何结论都附 `regimes.warm.objective.primary.relativeChange` 与 `regimes.long` 的 `nativeCompactions/quoteFailures`，因为它们回答的是 6.1 论点本身，独立于主决策。
- 不得写"全局最佳""2% 非劣""优于 Native"。

## 负例与边界

- 少任何一个 planned episode → 主决策 `inconclusive`，文档照写 `inconclusive` 并列出 `NOT_RUN` 清单。
- `/metrics` 中途 401 → engine 字段 unknown，`secondary["engine-prefill"].known=false`，主目标不受影响。
- engine identity 变化 → 该 episode `blocked`，继续；blocked > 20% → 停止并 `inconclusive`。
- 文档决策与 `report.json` 不一致 → `docs-decision-consistency` 红，不得通过改测试正则以外的方式绕过。
- 若 4090 不可用：S07 记 `BLOCKED`，文档维持第 7 轮 `inconclusive` 但必须把三次 dirty 诊断 run 的存在写进 HANDOFF "诊断数据" 小节（runId、`diagnosticOnly`、不作交付）。
