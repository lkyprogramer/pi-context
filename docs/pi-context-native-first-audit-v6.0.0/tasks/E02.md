# E02 · 判题与 Agent 在无凭据容器内运行

**目标**：模型写出的代码只在容器里编译运行；判题器与 Agent 分离；Agent 容器只能访问 4090 隧道端口。删除 `eval/live-g4.mjs` 的宿主 `javac/mvn` 路径。F16 关闭。

**依赖**：E01。
**先读**：[隔离要求](../testing/02-isolation.md)、现有 `eval/sandbox/Containerfile`（node 22.19 + JDK17 + maven + pi 0.85.1）、`eval/sandbox/build-image.mjs`、E01 的 `run-episode.mjs`。

## 文件边界

- `eval/local/grade.sh`
- `eval/local/sandbox/run-agent.sh`
- `eval/local/run-episode.mjs`
- `eval/sandbox/Containerfile`
- `eval/sandbox/build-image.mjs`
- `eval/live-g4.mjs`
- `test/security/grader-isolation.test.ts`

测试文件 `test/security/grader-isolation.test.ts` 必须在该列表。`eval/live-g4.mjs` 本任务删除（其 Java 用例已迁入 `eval/local/fixtures`，broker/凭据中继在本地栈无用）。`eval/sandbox/Containerfile` 只允许加 `git`（夹具基线）与 `--network` 无关的包，不改基础镜像 digest。

## 交付接口

**Consumes**：镜像 `pctx-t21-sandbox:0.85.1`；Docker Desktop 的 `host.docker.internal`；E01 的 episode 目录结构。

**Produces**：
- `eval/local/sandbox/run-agent.sh <workdir> <agentDir> <episodeDir> <windowProfile>`：`docker run --rm --network bridge --read-only --tmpfs /tmp --user 1000:1000 --cap-drop ALL --security-opt no-new-privileges --memory 4g --pids-limit 512 -v <workdir>:/work -v <agentDir>:/home/node/.pi/agent -v <repo>/dist:/plugin:ro -v <episodeDir>:/out pctx-t21-sandbox:0.85.1 node /out/run-in-container.mjs`；容器内 `models.json.baseUrl = http://host.docker.internal:18343/v1`；不挂载宿主 HOME、`.env`、SSH、Docker socket。
- `eval/local/grade.sh <caseId> <candidateDir> <outDir>`：`docker run --rm --network none --read-only --tmpfs /tmp --user 1000:1000 --cap-drop ALL --security-opt no-new-privileges -v <candidateDir>:/candidate:ro -v <trustedGraderDir>:/grader:ro -v <outDir>:/out`，容器内复制 `/candidate` 允许修改的源码到 `/tmp/build`，覆盖可信 `verify.sh`/`Oracle.java`/`pom.xml`，执行；写 `/out/grade.json{exitCode, passed, protectedIntact, outsideEditable, stdoutSha256, durationMs}`；`outsideEditable` = 候选目录中与可信夹具不同、且既不在 `editable` 也不在 `protectedPaths` 内的文件数（wrong-action 信号，在宿主侧比对，不进容器）。`passed = exitCode===0 && protectedIntact`；stdout 里的 `ORACLE_PASS` 不参与判定。`protectedIntact` = 候选目录内 `protectedPaths` 的 sha256 与夹具基线一致。
- H01/H02 的 nonce 判题：`grade.sh` 读取 `eval/local/seeds/<seed>.secret`（仅判题容器可见，只读挂载）比较目标文件内容。
- `run-episode.mjs`：`--sandbox`（默认开）时通过 `run-agent.sh` 运行 Agent，并在结束后调用 `grade.sh` 填 `EpisodeResult.oracle`；`--no-sandbox` 只允许 `H03` dogfooding。
- `eval/sandbox/build-image.mjs`：保持可重建；输出镜像 digest 到 stdout。

## 第一条行为 RED

```ts
import { spawnSync } from "node:child_process";
import { mkdtempSync, writeFileSync, readFileSync, mkdirSync } from "node:fs";
import { tmpdir } from "node:os";
import { join } from "node:path";
import { expect, it } from "vitest";

const repo = join(import.meta.dirname, "../..");
const docker = spawnSync("docker", ["version", "--format", "{{.Server.Version}}"], { encoding: "utf8" });
const dockerOk = docker.status === 0;   // no Docker → ctx.skip(): reported as blocked-environment, never counted as pass

it("a candidate that prints ORACLE_PASS but exits 1 is graded failed, and cannot reach the network", (ctx) => {
  if (!dockerOk) ctx.skip();
  const cand = mkdtempSync(join(tmpdir(), "pctx-cand-"));
  mkdirSync(join(cand, "src/main/java/com/acme/order"), { recursive: true });
  writeFileSync(join(cand, "src/main/java/com/acme/order/OrderService.java"), "public class OrderService { static { System.out.println(\"ORACLE_PASS:L01\"); } }\n");
  writeFileSync(join(cand, "verify.sh"), "#!/bin/sh\ncurl -m 3 http://example.com >/dev/null 2>&1 && echo NET_OK\necho ORACLE_PASS:L01\nexit 1\n");
  const out = mkdtempSync(join(tmpdir(), "pctx-grade-"));
  const r = spawnSync("bash", [join(repo, "eval/local/grade.sh"), "L01", cand, out], { encoding: "utf8" });
  expect(r.status).toBe(0);                               // grader itself ran
  const grade = JSON.parse(readFileSync(join(out, "grade.json"), "utf8"));
  expect(grade.passed).toBe(false);
  expect(grade.exitCode).not.toBe(0);
  expect(r.stdout + r.stderr).not.toContain("NET_OK");
});

it("candidate verify.sh is ignored in favour of the trusted grader copy", (ctx) => {
  if (!dockerOk) ctx.skip();
  const cand = mkdtempSync(join(tmpdir(), "pctx-cand-"));
  writeFileSync(join(cand, "verify.sh"), "#!/bin/sh\nexit 0\n");
  const out = mkdtempSync(join(tmpdir(), "pctx-grade-"));
  spawnSync("bash", [join(repo, "eval/local/grade.sh"), "L01", cand, out], { encoding: "utf8" });
  const grade = JSON.parse(readFileSync(join(out, "grade.json"), "utf8"));
  expect(grade.passed).toBe(false);                       // trusted verify.sh compiles real sources → fails on empty candidate
});
```

运行：

```bash
pnpm exec vitest run test/security/grader-isolation.test.ts --config vitest.config.ts
```

预期：`grade.sh` 不存在 → spawn 失败。Docker 不可用时测试 skip 并在 iterations 记录 `blocked-environment`；**skip 不是通过**，E03 前必须在有 Docker 的机器上实际绿。

## 实施顺序

1. `Containerfile` 加 `git`；重建镜像并记录 digest。
2. `run-agent.sh` 与容器内 `run-in-container.mjs`（由 `run-episode.mjs` 生成到 episodeDir：SDK 创建会话、prompt、写 events）。`baseUrl` 在容器内改写为 `host.docker.internal`。验证：容器内 `curl http://host.docker.internal:18343/v1/models` 通、`curl https://registry.npmjs.org` 不通（Docker Desktop 上用 `--network` 自定义 network + 仅放行 host 网关的做法若不可行，退而记录"容器可出网"为已知限制，并在 report 标注）。
3. `grade.sh`：可信 grader 目录 = `eval/local/fixtures/<case>/grader/` 或 CodexGame 夹具的 `verify.sh + src/test`；候选只复制 `src/main/**`；H 系列加 nonce 比较。
4. `run-episode.mjs` 集成；`--no-sandbox` 仅 H03。
5. 删除 `eval/live-g4.mjs`；`grep -rn "javac\|mvn" eval/` 只应命中容器内脚本。
6. 校准：对 L01–L06 的 `initial/` 直接判题必须 `passed=false`；对 `grader/KnownGood.java.txt`（或 CodexGame 夹具的已知修复）判题必须 `passed=true`。

## 必测负例及边界

- 候选修改 `pom.xml`/`verify.sh`/`src/test/**` → `protectedIntact=false` → failed。
- 候选含 symlink 指向 `/etc/passwd` → 复制阶段拒绝，failed。
- 候选 `System.exit(0)` 在测试前 → 测试数不达预期 → failed（可信 verify.sh 在 JUnit/自写 Test 后检查输出计数或以 Oracle exit code 为准）。
- 判题超时 300 s → `timeout`。
- Agent 容器内读 `/home/node/.pi/agent/auth.json` 只应看到 `{}`；没有宿主 `~/.pi`。
- `run-agent.sh` 找不到 `pctx-t21-sandbox:0.85.1` → `blocked`，不回退宿主执行。

## 验收与结束

```bash
node eval/sandbox/build-image.mjs
pnpm exec vitest run test/security/grader-isolation.test.ts --config vitest.config.ts

```

最终验收：known-bad 判 failed、known-good 判 passed；Agent 与判题都在容器；宿主没有 `javac`/`mvn` 执行路径；一次真实容器 episode 跑通。
