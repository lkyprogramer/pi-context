# A01 · 官方 ExtensionAPI 类型、真实配置加载、status 与 compactionEntry

**目标**：入口和 adapter 用官方导出类型；用户配置文件真正决定运行 profile；`/pctx status` 报告真实身份；`session_compact` 读对字段。F01、F02 关闭。

**依赖**：无。
**先读**：[目标设计](../design/00-target.md) §三种模式、[合同](../design/01-contracts.md) §1/§5、[Pi 事实](../audit/05-native-pi.md)、`node_modules/@earendil-works/pi-coding-agent/dist/core/extensions/types.d.ts`。

## 交付接口

**Consumes**：官方 `ExtensionAPI`、`ExtensionContext`、`SessionCompactEvent`（`compactionEntry`、`fromExtension`、`reason`、`willRetry`）、`ContextEvent`、`MessageEndEvent`；现有 `loadConfig(cwd, projectTrusted)`。

**Produces**：
- `export default function register(pi: ExtensionAPI): void`，adapter 各 `pi.on(...)` 回调参数不再是 `Record<string, unknown>`。
- `PctxConfig.schemaVersion=6`，新增 `fold` 段，删除 `checkpoint`/`semantic`/`projection` 段（本任务先在 parseConfig 拒绝旧字段并给出迁移提示；C01 删代码）。`loadConfig` 返回 `warnings`，发现 `pctx-v5.json` 时追加 `ignored-legacy-config`。
- `session_start` 里调用 `loadConfig(ctx.cwd, projectTrusted)`；加载失败 → profile 强制 `observe`、`warnings` 含错误、`ctx.ui.notify` 一次。
- `/pctx status` 输出 `StatusView` 的 `resolvedProfile/configHash/configSource/warnings/hostVersion/contextWindow/contextPercent`（后两项来自 `ctx.getContextUsage()`；`hostVersion` 来自宿主 package.json 的 `version`）。
- `session_compact` 用 `event.compactionEntry.id/summary`，并记录 `reason/willRetry`。

`projectTrusted` 的来源：`ctx.settingsManager`/宿主是否把项目标为 trusted；若官方 API 无直接布尔量，只信任 `~/.pi/agent/pctx.json`，项目文件需要 `settings.json` 的 `defaultProjectTrust: "always"`，并在 status 里说明来源。不得默认信任 cwd 文件。

## 第一条行为 RED

```ts
import { mkdtempSync, mkdirSync, writeFileSync } from "node:fs";
import { tmpdir } from "node:os";
import { join } from "node:path";
import { expect, it } from "vitest";
import { loadConfig } from "../../src/config.js";

it("a trusted project pctx.json switches the effective profile to balanced", () => {
  const cwd = mkdtempSync(join(tmpdir(), "pctx-cfg-"));
  mkdirSync(join(cwd, ".pi"));
  writeFileSync(join(cwd, ".pi", "pctx.json"), JSON.stringify({ schemaVersion: 6, profile: "balanced" }));
  const loaded = loadConfig(cwd, true);
  expect(loaded.config.profile).toBe("balanced");
  expect(loaded.config.fold.triggerPercent).toBe(60);
  expect(loaded.source).toBe(join(cwd, ".pi", "pctx.json"));
  expect(loadConfig(cwd, false).config.profile).toBe("observe");
});

it("rejects legacy schemaVersion 5 fields with a migration message", () => {
  expect(() => loadConfig.parse({ schemaVersion: 5, profile: "observe", semantic: { enabled: true } }))
    .toThrow(/schemaVersion 6|remove semantic/);
});
```

运行：

```bash
pnpm exec vitest run test/unit/config-effective.test.ts --config vitest.config.ts
```

预期：当前 `loadConfig` 读 `pctx-v5.json`、`schemaVersion` 只接受 5，没有 `fold` 段 → 断言失败。`test/host/config-activation.test.ts` 的第一条 RED：用官方 `createAgentSession` 加载 `dist/extension.js`，在 cwd 放 `.pi/pctx.json` balanced，执行 `/pctx status`，期望输出含 `profile=balanced`；当前入口忽略文件，输出 observe。

## 实施顺序

1. `package.json` 加 `@earendil-works/pi-coding-agent@0.85.1` 到 `devDependencies`（类型来源；运行时仍由宿主提供），`tsconfig.build.json` 确认 `types` 可解析；`src/extension.ts` 改为 `import type { ExtensionAPI } from "@earendil-works/pi-coding-agent"`。
2. `src/pi/adapter.ts`：每个 `pi.on` 的 event/ctx 用官方类型；`session_compact` 改 `event.compactionEntry`；`message_end` 提取 `event.message.usage` 与 `stopReason` 交给 `src/telemetry/metrics.ts` 的 `recordAssistant()`（C03 再扩展为 RequestRecord）。
3. `src/config.ts`：`schemaVersion: 6`、`fold` 默认值、`storage.dbPath`、`telemetry.jsonl`；`parseConfig` 拒绝未知字段、NaN、负数、`triggerPercent>=85`、`targetPercent>=triggerPercent`；`loadConfig` 文件名 `pctx.json`，返回 `warnings`。
4. `session_start`：加载配置并写入 `state.config/configHash/configSource/warnings`；失败回退 observe 并通知。
5. `src/commands.ts`：`/pctx status` 输出 `StatusView`（本任务能填的字段；其余字段留 `null` 并在 C03 填）；`/pctx profile <p>` 只改内存并提示"不会写回配置文件"。
6. `docs/CONFIGURATION.md` 重写为 6.1 配置：路径、字段、默认值、trust 规则、旧文件处理。

## 必测负例及边界

- `.pi/pctx.json` 在 `projectTrusted=false` 时被忽略且 `warnings` 含 `untrusted-project-config`。
- `{"schemaVersion":6,"fold":{"triggerPercent":90}}` → CONFIG_ERROR（超过 85）。
- `{"schemaVersion":6,"telemetry":{"includeContent":true}}` → CONFIG_ERROR。
- 存在 `~/.pi/agent/pctx-v5.json` 而无 `pctx.json` → 使用默认并 `ignored-legacy-config`。
- `session_compact` 事件 `willRetry=true` 时不把摘要计为一次完成的压缩。
