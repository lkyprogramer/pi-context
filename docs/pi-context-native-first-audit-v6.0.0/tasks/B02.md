# B02 · scope 安全检索、真分页、增量 SQLite FTS5 索引与关闭

## 交付接口

**Consumes**：B01 `FieldRef`/hash；`ctx.sessionManager.getEntries()`、`getLeafId()`、entry `parentId` 链（可信来源）；`SearchCursor` 合同。

**Produces**：
- `HistoryIndex` 用 `node:sqlite` `DatabaseSync` + FTS5：表 `blocks(workspace_id, session_id, entry_id, block_index, source_hash, tool_name, byte_len, indexed_at)` 与 `blocks_fts(text, content='blocks_text')`。`search` 的 SQL：`WHERE b.session_id = ? AND b.entry_id IN (可见集合临时表) ... ORDER BY bm25 LIMIT ? OFFSET ?`。不在 JS 里先排序再过滤。
- `SearchCursor{ v:6, sessionId, branchHash, queryHash, indexRevision, offset }`；cursor 的任何字段与当前请求不一致 → `CURSOR_MISMATCH`，从 0 重新开始并说明。
- `upsertBranch(scope, entries)` 用 `INSERT OR IGNORE`；每 session 记录 `lastIndexedLeaf`，相同 leaf 直接返回 `{inserted:0}`。
- 跳过 `toolName === "pctx_history"` 的 toolResult 和所有非 toolResult/非 user/assistant 文本以外的块（只索引 toolResult text 与 assistant/user text）。
- `close()` 在 `session_shutdown` 与 `session_start`（切换会话）调用；`storage.mode="persistent"` 时 `dbPath` 必须是文件路径（默认 `~/.pi/agent/pctx/index.sqlite`），`:memory:` 只在 `memory-only`。status 显示真实 `indexMode/dbPath/rows/bytes`。
- `src/history/scope.ts`：`scopeFor(ctx): Scope`，用 `parentId` 从 leaf 回溯生成 `visibleEntryIds`；`workspaceId = sha256(realpath(cwd)).slice(0,16)`。

## 第一条行为 RED

```ts
import { expect, it } from "vitest";
import { createHistoryIndex } from "../../src/history/index.js";
import type { NativeEntry, Scope } from "../../src/contracts.js";

function tr(id: string, parent: string | null, text: string): NativeEntry {
  return { id, parentId: parent, type: "message", message: { role: "toolResult", toolCallId: `c-${id}`, toolName: "bash", isError: false, content: [{ type: "text", text }] } };
}

it("never ranks or returns blocks outside the visible session scope", async () => {
  const idx = await createHistoryIndex({ mode: "memory-only", dbPath: null, maxIndexBytes: 1 << 20 });
  const a: Scope = { workspaceId: "w", sessionId: "A", leafId: "a1", visibleEntryIds: new Set(["a1"]) };
  const b: Scope = { workspaceId: "w", sessionId: "B", leafId: "b1", visibleEntryIds: new Set(["b1"]) };
  await idx.upsertBranch(a, [tr("a1", null, "PRIVATE_SYNTHETIC_A appears here")]);
  await idx.upsertBranch(b, [tr("b1", null, "ordinary text")]);
  const hits = await idx.search(b, "PRIVATE_SYNTHETIC_A", 8, 0);
  expect(hits).toEqual([]);
  const own = await idx.search(a, "PRIVATE_SYNTHETIC_A", 8, 0);
  expect(own.map((h) => h.entryId)).toEqual(["a1"]);
  await idx.close();
});

it("offset paginates without duplicates", async () => {
  const idx = await createHistoryIndex({ mode: "memory-only", dbPath: null, maxIndexBytes: 1 << 20 });
  const s: Scope = { workspaceId: "w", sessionId: "S", leafId: "e5", visibleEntryIds: new Set(["e1","e2","e3","e4","e5"]) };
  await idx.upsertBranch(s, [1,2,3,4,5].map((n) => tr(`e${n}`, n === 1 ? null : `e${n-1}`, `needle block ${n}`)));
  const p1 = await idx.search(s, "needle", 2, 0);
  const p2 = await idx.search(s, "needle", 2, 2);
  const p3 = await idx.search(s, "needle", 2, 4);
  const ids = [...p1, ...p2, ...p3].map((h) => h.entryId);
  expect(new Set(ids).size).toBe(5);
  expect(ids).toHaveLength(5);
  await idx.close();
});
```

## 实施顺序

1. `src/history/scope.ts`：`scopeFor(ctx)`；`src/pi/source-reader.ts` 提供 `branchEntries(sessionManager)`（leaf → root 正序）与 `toolResultByCallId`。
2. `src/history/index.ts` 重写为 `node:sqlite` 实现；删除 in-memory Map 搜索；FTS5 不可用时抛 `INDEX_UNAVAILABLE`，status 显示 `history: unavailable`，不静默降级。
3. `search` 的 scope 谓词、`LIMIT/OFFSET`、`revision()`（`max(indexed_at) || count`）。
4. `src/history/search.ts` 组装 `SearchCursor` 与 `CURSOR_MISMATCH` 处理；`nextCursor` 仅在 `hits.length === limit` 时给出。
5. `src/plugin.ts`：`session_start` 打开索引并 `upsertBranch` 当前分支；`tool_result`/`turn_end` 后增量 upsert；`session_shutdown` `close()`。`pctx_history` 的自身结果按 `toolName` 排除。
6. `src/commands.ts` status 加 `indexMode/dbPath/rows/bytes/lastIndexedLeaf`。
7. `test/host/index-restart.test.ts`：官方 `SessionManager` 建会话 → 写入 → `dispose` → `open` 同一文件 → 再 `upsertBranch` 应 `inserted:0` 且 search 命中一致。

## 必测负例及边界

- 相同 `entryId` 出现在两个 session（synthetic）：B 搜不到 A 的正文。
- 同一 session 的 sibling branch：切换 leaf 后 sibling 的 block 不返回。
- cursor 的 `queryHash` 与当前 query 不同 → `CURSOR_MISMATCH`，不静默从 offset 继续。
- `pctx_history` 搜索结果本身含关键词，再次搜索不得命中它（回声排除）。
- `maxIndexBytes` 超限 → 拒绝新写入并在 status 标 `index-full`，search 仍可用。
- `persistent` 且 `dbPath` 目录不可写 → CONFIG_ERROR，不是 `:memory:`。
