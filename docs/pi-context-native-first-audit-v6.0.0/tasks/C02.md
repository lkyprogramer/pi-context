# C02 · 派生暴露与批次保护

**目标**：用原生日志派生"哪些 toolResult 已经进入过一次成功请求"，替代 ledger；批次按官方字段判断完整/错误/非文本并生成保护集。F10 关闭。

**依赖**：C01、B01。
**先读**：[折叠算法](../design/02-fold-algorithm.md) §2/§3、[合同](../design/01-contracts.md) §4、现有 `src/projection/batches.ts`、`test/unit/batches.test.ts`。

## 交付接口

**Consumes**：`branchEntries()` 给出的分支顺序 `NativeEntry[]`；官方字段 `toolResult.isError`、`assistant.stopReason`、`assistant.usage`。

**Produces**：
- `exposedEntryIds(entries): Set<string>`：toolResult 之后出现 `stopReason ∉ {"error","aborted"}` 且 `usage.totalTokens>0 || usage.input>0` 的 assistant，则该 toolResult 已暴露。最后一批尚无成功响应 → 未暴露。
- `collectBatches(entries): ToolBatch[]`：以含 toolCall 的 assistant entry 为批次锚；`complete` = 每个 call 恰一个 result；`hasNonText`；`results[].isError` 直接取字段。
- `protectSet(batches, K): Set<entryId>`：最近 K 个完整批次 ∪ 不完整批次 ∪ 含 isError 结果批次 ∪ hasNonText 批次的全部 result entryId。
- `src/pi/source-reader.ts`：`toolResultIndex(entries): Map<toolCallId, entryId | "ambiguous">`（重复 callId → ambiguous）。

## 第一条行为 RED

```ts
import { expect, it } from "vitest";
import { exposedEntryIds } from "../../src/projection/exposed.js";
import { collectBatches, protectSet } from "../../src/projection/batches.js";
import type { NativeEntry } from "../../src/contracts.js";

const ok = { input: 10, output: 5, cacheRead: 0, cacheWrite: 0, totalTokens: 15 };
const a = (id: string, parent: string | null, calls: string[], stop = "toolUse", usage = ok): NativeEntry =>
  ({ id, parentId: parent, type: "message", message: { role: "assistant", stopReason: stop, usage, content: calls.map((c) => ({ type: "toolCall", id: c, name: "bash", arguments: {} })) } });
const r = (id: string, parent: string, call: string, isError = false): NativeEntry =>
  ({ id, parentId: parent, type: "message", message: { role: "toolResult", toolCallId: call, toolName: "bash", isError, content: [{ type: "text", text: `out-${id}` }] } });

it("derives exposure only from a later successful assistant entry", () => {
  const entries = [
    a("a1", null, ["c1"]), r("r1", "a1", "c1"),
    a("a2", "r1", ["c2"]), r("r2", "a2", "c2"),
    a("a3", "r2", [], "error", { ...ok, totalTokens: 0, input: 0 }),   // failed request: r2 not exposed by it
  ];
  const exposed = exposedEntryIds(entries);
  expect(exposed.has("r1")).toBe(true);
  expect(exposed.has("r2")).toBe(false);
});

it("protects error batches and the last K complete batches", () => {
  const entries: NativeEntry[] = [
    a("a1", null, ["c1"]), r("r1", "a1", "c1"),
    a("a2", "r1", ["c2"]), r("r2", "a2", "c2", true),
    a("a3", "r2", ["c3", "c4"]), r("r3", "a3", "c3"),           // c4 missing → incomplete
    a("a4", "r3", ["c5"]), r("r5", "a4", "c5"),
  ];
  const batches = collectBatches(entries);
  expect(batches.map((b) => b.complete)).toEqual([true, true, false, true]);
  const protect = protectSet(batches, 1);
  expect(protect.has("r5")).toBe(true);   // last complete batch
  expect(protect.has("r2")).toBe(true);   // isError
  expect(protect.has("r3")).toBe(true);   // incomplete batch
  expect(protect.has("r1")).toBe(false);
});
```

## 实施顺序

1. `src/contracts.ts` 写 `ToolBatch` 类型；`src/pi/source-reader.ts` 加 `toolResultIndex`。
2. `src/projection/exposed.ts` 实现 `exposedEntryIds`（单次线性扫描）。
3. `src/projection/batches.ts` 重写 `collectBatches/protectSet`：不再接受 `isExposed` 回调；`complete` 用精确计数；`hasNonText` 扫描 content 类型。
4. 更新 `test/unit/batches.test.ts` 到新签名，保留原有边界（乱序结果、duplicate、兄弟分支同 callID 通过 `toolResultIndex` 的 ambiguous 处理）。

## 必测负例及边界

- 同批两 call 结果乱序：仍 complete。
- duplicate result（同 callId 两条）：不 complete；`toolResultIndex` 返回 ambiguous。
- 分支上存在 compaction entry：其后的 assistant 仍算成功响应；compaction 之前的 entry 不出现在 `entries`（由 `branchEntries` 保证，单测用输入模拟）。
- `usage` 缺失（老日志）→ 视为未暴露，不猜。
- 最后一个 assistant `stopReason="aborted"`（用户中断）→ 其前一批未暴露。
- 只有 assistant text（无 toolCall）的 entry 不形成批次，但作为成功响应参与暴露判断。
