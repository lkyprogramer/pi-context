# D01 · 真官方 Pi + 受控 provider 的接线测试

**目标**：在全局安装的官方 pi 0.85.1 里，用 `ModelRuntime.registerProvider` 的 `streamSimple` 受控 provider 捕获**真正发往 provider 的 messages**，证明 observe 逐字节不变、balanced 折叠/保护/回读/前缀稳定/compact 清空成立，并把它收成 `pnpm smoke`。F20 关闭。

**依赖**：C03、B03。
**先读**：[合同](../design/01-contracts.md) §4、现有 `test/packed/install.test.ts`（受控 provider 写法）、`test/helpers/official-pi.ts`、`eval/sandbox/g4-agent.mjs`（`sessionManager.appendMessage` 造历史）。

## 交付接口

**Consumes**：`loadOfficialPi()`；`createAgentSession({ ..., modelRuntime, model, noTools: "builtin" })`；插件通过 `settings.json.extensions=[<abs dist/extension.js>]` 或 tarball 安装加载；`.pi/pctx.json` 决定 profile。

**Produces**：
- `test/helpers/controlled-provider.ts`：`registerControlledProvider(runtime, { contextWindow, script })`，`streamSimple(model, context)` 记录每次 `context.messages` 的 `structuredClone` 与 `JSON.stringify` 字节到 `captured[]`，按 `script` 返回 assistant（text 或 toolCall）并带 `usage{input = estimateTokens(messages), cacheRead, output, totalTokens}`。
- `test/host/observe-identity.test.ts`：observe 下 3 次请求，`captured[i]` 与"不加载插件"对照会话的同序请求字节相同（除 timestamp 字段外）。
- `test/host/balanced-wire.test.ts`：
  1. `contextWindow=12000`，`.pi/pctx.json` `{schemaVersion:6, profile:"balanced", fold:{triggerPercent:60,targetPercent:40,protectRecentBatches:1,minRemovedTokens:500}}`；
  2. 用 `sessionManager.appendMessage` 造 6 组 user→assistant(toolCall)→toolResult（每个 toolResult 约 1500 字符）并追加一条成功 assistant（usage.totalTokens>0）；
  3. `session.prompt("continue")`：受控 provider 捕获的 messages 中前 5 组 toolResult 为 stub（含 `pctx:6:`）、第 6 组原文、user/assistant 未变、消息数与 toolCallId 序列相同；
  4. 通过 `session` 调用 `pctx_history read` stub 里的 ref（用工具调用脚本让模型"请求"或直接 `session.getActiveTools()` 找到工具执行），返回正文与造历史时的原文相同，`details.verified===true`；
  5. 再 `session.prompt("again")`：第二次捕获的前缀（到最后一个 stub 消息为止）与第一次逐字节相同；
  6. `await session.compact()` 成功后再 `prompt`：`/pctx status` 的 `activePlan` 为 null，`nativeCompactions=1`；
  7. 整个过程 session JSONL 的 sha256 在插件运行前后仅因新增 entry 变化：旧行逐行相同（读文件比对前 N 行）。
- `pnpm smoke` = `vitest run test/host/observe-identity.test.ts test/host/balanced-wire.test.ts test/packed/install.test.ts`。

## 第一条行为 RED

```ts
import { expect, it } from "vitest";
import { loadOfficialPi } from "../helpers/official-pi.js";
import { registerControlledProvider, seedToolHistory, openBalancedSession } from "../helpers/controlled-provider.js";

it("balanced folds only old exposed tool results and keeps the wire structure", async () => {
  const pi = await loadOfficialPi();
  const { session, manager, captured, cwd } = await openBalancedSession(pi, { contextWindow: 12000, protectRecentBatches: 1 });
  const seeded = seedToolHistory(manager, { batches: 6, resultChars: 1500 });
  await session.prompt("continue");
  const wire = captured.at(-1)!.messages;
  const results = wire.filter((m) => m.role === "toolResult");
  expect(results).toHaveLength(6);
  expect(results.slice(0, 5).every((m) => JSON.stringify(m.content).includes("pctx folded tool result"))).toBe(true);
  expect(JSON.stringify(results[5].content)).toContain(seeded.originals[5].slice(0, 40));
  expect(wire.map((m) => m.role)).toEqual(captured.at(-1)!.roles);
  const stubRef = /pctx:6:[A-Za-z0-9_-]+/.exec(JSON.stringify(results[0].content))![0];
  const read = await session.executeTool?.("pctx_history", { action: "read", ref: stubRef });
  expect(JSON.stringify(read)).toContain(seeded.originals[0].slice(0, 200));
  await session.prompt("again");
  const first = JSON.stringify(captured.at(-2)!.messages.slice(0, 18));
  const second = JSON.stringify(captured.at(-1)!.messages.slice(0, 18));
  expect(second).toBe(first);
  await session.dispose?.();
  void cwd;
});
```

## 实施顺序

1. `test/helpers/controlled-provider.ts`：注册 provider、捕获、脚本化响应、`seedToolHistory`、`openBalancedSession`（临时 HOME/agentDir/cwd、写 `.pi/pctx.json`、`settings.json.extensions` 指向 `dist/extension.js`，先 `pnpm build`）。
2. `test/helpers/official-pi.ts`：补 `executeTool`/`getActiveTools` 等本测试用到的类型声明（按 0.85.1 实际导出名核对 `dist/index.d.ts`，不存在的方法不要声明）。
3. `observe-identity`：两会话（有/无插件）同脚本，比较去 timestamp 后的 JSON。
4. `balanced-wire` 七步；`/compact` 用 `session.compact()`，若受控 provider 不支持摘要请求则 script 提供一条摘要 assistant。
5. `test/packed/install.test.ts`：安装 tarball 后同样跑 observe-identity 一次（复用 helper）。
6. `scripts/packed-host.mjs` 输出 tarball sha256 到 JSON 行；`package.json` 加 `smoke`。

## 必测负例及边界

- `protectRecentBatches=1` 且只有 1 个批次 → 不折叠，`captured` 与输入相同。
- 造历史时最后一批没有后继成功 assistant → 该批原文。
- 某 toolResult `isError:true` → 原文。
- 受控 provider 返回 `stopReason:"error"` 的响应之后新增的批次不算暴露。
- 切换 `.pi/pctx.json` 为 observe 后重开会话 → 无 stub。
- JSONL 旧行 sha 不变。
