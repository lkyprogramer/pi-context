# B01 · 统一字段引用 refForField 与 UTF-8 hash 口径

**目标**：search、fold stub、read 三处的引用来自同一个函数；多 block 不再全部指向 block 0；text/image hash 口径唯一。F03、F04 关闭。

**依赖**：A01。
**先读**：[合同](../design/01-contracts.md) §2、[findings F03/F04](../audit/03-findings.md)、现有 `src/history/refs.ts`、`src/history/search.ts` 的 `indexOf`/`blockIndex: 0` 处。

## 文件边界

- `src/contracts.ts`
- `src/history/refs.ts`
- `src/history/search.ts`
- `src/history/read.ts`
- `src/history/index.ts`
- `src/plugin.ts`
- `test/unit/field-ref.test.ts`

测试文件 `test/unit/field-ref.test.ts` 必须在该列表。`src/history/index.ts` 只改行主键/hash 写入口径（`(workspace_id, session_id, entry_id, block_index, source_hash)`），检索逻辑留给 B02。

## 交付接口

**Consumes**：`Scope`、`NativeEntry`（官方 `SessionEntry` 的 message 子集）。

**Produces**：
- `refForField(scope, entry, blockIndex): FieldRef | RefError`：越界、非 text/image、缺 id、entry ∉ scope → 错误码 `REF_OUT_OF_RANGE / REF_KIND / REF_ENTRY / REF_SCOPE`。
- `encodeRef/decodeRef` 版本 `6`；旧版本 ref 解码为 `REF_VERSION` 错误，不做兼容。
- `textSourceHash(text) = sha256(Buffer.from(text,"utf8"))`；`imageSourceHash(block) = sha256(canonicalJSON({type,mimeType,data}))`。所有写 hash 的地方（索引、stub、read 校验）调用这两个函数。
- `search` 的每个 hit 用 `refForField(scope, entry, i)` 生成，`i` 是命中的真实 block 下标；hit.excerpt 来自该 block。

## 第一条行为 RED

```ts
import { expect, it } from "vitest";
import { refForField, decodeRef, textSourceHash } from "../../src/history/refs.js";
import type { NativeEntry, Scope } from "../../src/contracts.js";

const scope: Scope = { workspaceId: "w1", sessionId: "s1", leafId: "r", visibleEntryIds: new Set(["r"]) };
const entry: NativeEntry = {
  id: "r", parentId: null, type: "message",
  message: { role: "toolResult", toolCallId: "c", toolName: "read", isError: false,
    content: [{ type: "text", text: "alpha" }, { type: "text", text: "Ω🙂 second" }, { type: "image", mimeType: "image/png", data: "iVBORw0KGgo=" }] },
};

it("returns one ref per block with per-block hash and kind", () => {
  const second = refForField(scope, entry, 1);
  const image = refForField(scope, entry, 2);
  expect("blockIndex" in second && second.blockIndex).toBe(1);
  expect("sourceHash" in second && second.sourceHash).toBe(textSourceHash("Ω🙂 second"));
  expect("kind" in image && image.kind).toBe("image");
  expect(refForField(scope, entry, 3)).toMatchObject({ code: "REF_OUT_OF_RANGE" });
  expect(refForField({ ...scope, visibleEntryIds: new Set() }, entry, 0)).toMatchObject({ code: "REF_SCOPE" });
  const round = decodeRef(encodeRefOf(second));
  expect(round).toEqual(second);
});
```

（`encodeRefOf` 即 `encodeRef`，测试里按最终导出名调用。）运行：

```bash
pnpm exec vitest run test/unit/field-ref.test.ts --config vitest.config.ts
```

预期：现有 `search.ts` 固定 `blockIndex: 0`、hash 口径在 `indexOf` 拼接文本上，函数 `refForField` 不存在 → 先 import 失败，实现后须证明把 `blockIndex` 硬编为 0 会让 `toBe(1)` 断言失败。

## 实施顺序

1. `src/contracts.ts` 写 `Scope`、`FieldRef`、`RefError` 类型与错误码常量。
2. `src/history/refs.ts` 实现 `refForField/encodeRef/decodeRef/textSourceHash/imageSourceHash`；删除旧 `entryRef`/拼接式 hash。
3. `src/history/search.ts`：命中定位改为按 block 遍历；返回 `IndexedHit{entryId, blockIndex, sourceHash, toolName, excerpt}`；删除对整条 entry 文本 `indexOf` 的依赖（分页在 B02）。
4. `src/history/read.ts`：`decodeRef` 后用 `refForField(scope, entry, ref.blockIndex)` 重新计算并比较 `sourceHash`，不等 → `STALE_REF`。
5. `src/history/index.ts`：写入行携带 `block_index/source_hash`，一 block 一行。
6. `src/plugin.ts`：`historyTool` 的 search/read 改用新签名；stub 生成暂用 `refForField`（C03 完整接入）。

## 必测负例及边界

- 同一 entry 三个 block：每个 ref 不同、hash 不同；第二 block 正文含 `Ω🙂` 时 hash 与 `Buffer.byteLength` 口径一致。
- 图片 block 的 hash 不受 `data` 之外字段顺序影响（canonical JSON）。
- `decodeRef("pctx:5:...")` → `REF_VERSION`。
- entry 在 sibling branch（不在 `visibleEntryIds`）→ `REF_SCOPE`，即使 sessionId 相同。
- 正文为空字符串的 text block 允许有 ref（bytes=0），但 C03 不会折叠它。
