# B00 — 冻结当前源码、CI、报告与审计证据

## 元数据

- Wave：`W0`
- Depends on：无
- Findings：NF030
- Completion：RED、GREEN、NARROW、FULL-GATE、Evidence Seal、当前 HEAD 绑定必须同时成立。

## 目标

建立不可变审计基线，固定附件 SHA、GitHub HEAD、Workflow Run、Live 报告和旧 Task 状态。

## 允许修改

- `audit-v2/**`
- `evidence/**`

禁止扩大 Scope。发现依赖缺口时写 blocker，并由 Controller 生成新的显式任务；不得在本任务中顺手改动其他生产层。

## 执行步骤

1. 编写测试：任一 evidence 文件修改后 manifest 校验失败
2. 生成 source/CI/report inventory
3. 记录已执行与未执行验证边界

## RED 测试要求

- 先写能稳定复现缺陷的测试；失败必须来自目标行为，不得来自缺依赖、路径或凭证。
- 对 concurrency/time/network 相关任务必须使用可控 Clock、Barrier、Recorded Provider Response 或独立 Live Lane。
- 测试名称不得使用 `live`，除非真实启动 Pi、真实加载当前 tarball/extension 并调用真实 Provider。

## 验收命令

```bash
python3 scripts/validate_artifacts.py
shasum -a 256 -c MANIFEST.sha256
```

## 验收不变量

1. 所有 Findings 的 observation 均有直接反例测试。
2. 不允许常量指标、字符串 Stub、预编程正确 Executor 或把缺失证据记为 0。
3. Abort/timeout/scope mismatch 必须 typed fail；失败样本保留。
4. Full Gate 必须在干净树、当前 HEAD、固定依赖与独立临时目录运行。
