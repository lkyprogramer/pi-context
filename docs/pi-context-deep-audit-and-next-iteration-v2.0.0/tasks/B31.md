# B31 — 统一 CI、Publication Gate 与 Release Claim Policy

## 元数据

- Wave：`W4`
- Depends on：B01, B05, B06, B28, B29, B30
- Findings：NF015, NF024, NF027, NF028
- Completion：RED、GREEN、NARROW、FULL-GATE、Evidence Seal、当前 HEAD 绑定必须同时成立。

## 目标

Release 必须同时满足 Required+Compatibility、当前 HEAD、完整 Live Bundle、Hard/Quality/Efficiency、package policy；否则 keep-native/no publication。

## 允许修改

- `.github/workflows/**`
- `packages/benchmark/src/report/**`
- `scripts/release/**`
- `docs/**`

禁止扩大 Scope。发现依赖缺口时写 blocker，并由 Controller 生成新的显式任务；不得在本任务中顺手改动其他生产层。

## 执行步骤

1. Gate 输入类型区分 synthetic/component/live-publication
2. liveProvider=false 永不 publicationClaim=true
3. Semantic Beta 继续独立 default-off

## RED 测试要求

- 先写能稳定复现缺陷的测试；失败必须来自目标行为，不得来自缺依赖、路径或凭证。
- 对 concurrency/time/network 相关任务必须使用可控 Clock、Barrier、Recorded Provider Response 或独立 Live Lane。
- 测试名称不得使用 `live`，除非真实启动 Pi、真实加载当前 tarball/extension 并调用真实 Provider。

## 验收命令

```bash
pnpm check:all
pnpm test:packed

node scripts/release/verify.mjs
```

## 验收不变量

1. 所有 Findings 的 observation 均有直接反例测试。
2. 不允许常量指标、字符串 Stub、预编程正确 Executor 或把缺失证据记为 0。
3. Abort/timeout/scope mismatch 必须 typed fail；失败样本保留。
4. Full Gate 必须在干净树、当前 HEAD、固定依赖与独立临时目录运行。
