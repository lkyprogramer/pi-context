# B11 — Context 与 Compaction 共用 Atomic RuntimeSnapshot

## 元数据

- Wave：`W1`
- Depends on：B08
- Findings：NF006
- Completion：RED、GREEN、NARROW、FULL-GATE、Evidence Seal、当前 HEAD 绑定必须同时成立。

## 目标

用单个 snapshot transaction 返回 directives/claims/continuity/pointers/heads/source boundary，禁止 compaction 分散查询。

## 允许修改

- `packages/runtime/src/runtime-snapshot.ts`
- `packages/storage-node/src/state-store.ts`
- `apps/pi-context-runtime/src/composition-root.ts`

禁止扩大 Scope。发现依赖缺口时写 blocker，并由 Controller 生成新的显式任务；不得在本任务中顺手改动其他生产层。

## 执行步骤

1. RED：并发 supersession/tool admission 时 snapshot 不得 torn
2. Materialize 与同 boundary compaction 记录相同 snapshotHash
3. SQLite transaction 支持 AbortSignal

## RED 测试要求

- 先写能稳定复现缺陷的测试；失败必须来自目标行为，不得来自缺依赖、路径或凭证。
- 对 concurrency/time/network 相关任务必须使用可控 Clock、Barrier、Recorded Provider Response 或独立 Live Lane。
- 测试名称不得使用 `live`，除非真实启动 Pi、真实加载当前 tarball/extension 并调用真实 Provider。
