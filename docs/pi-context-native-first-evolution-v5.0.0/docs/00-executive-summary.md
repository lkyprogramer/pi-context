# 00 · 执行摘要：做小边界，做强恢复，按真实任务证明收益

## 1. 最重要的判断

pi-context 已经不是一个简单摘要插件。当前代码已经具备独立运行时、原始观察封装、持久化、来源授权、用户输入回执及实验体系。继续把“外置记忆＋运行时”作为全新目标，会重复过去几轮工作，进一步扩大复杂度。[S01–S06](../SOURCE-INDEX.md)

真正需要调整的是**谁拥有事实、谁控制生命周期、在哪个时刻允许有损、如何证明净收益**。建议让 Pi 重新成为唯一会话事实源及压缩调度者，把插件收敛为三个协作部件：

1. **Evidence History**：以 Pi 原生 entry 为来源，可重建的本地索引与有限回读。
2. **Stable Context Projection**：只对已经进入过成功请求的旧工具观察做可逆视图缩减，不改原始会话，不动未消费批次。
3. **Source-backed Checkpoint**：在原生压缩后补一小块带来源的必要工作状态；可选语义生成放到实验层。

这不是“不要记忆”，而是**不再为已有的宿主能力建立第二套竞争性实现**。

## 2. 本次确认的事实改变了上一轮建议

**Pi 原生保存旧历史。** 原生 compaction 只是改变发给模型的工作视图，不把旧 JSONL 记录永久删除；当前源码也已包含工具批次之间的压缩阈值检查。把它描述成“只有摘要，旧历史已丢失”不准确。[S08–S10](../SOURCE-INDEX.md)

**当前 pi-context 并非未修改官方 Pi 的即装即用插件。** 它固定 0.84.4 的补丁版本，加载时检查自定义 `PCR_INGRESS_METADATA_CONTRACT`。项目自己如实声明这个限制。本次应主动改变该取舍，取消 patch、额外 input 元数据和输入拒绝协议，而不是仅更改 peerDependencies。[S02、S29](../SOURCE-INDEX.md)

**最新实测仍不足以证明比 Native 更好。** 24 个计划配对只有16个完整配对，真实代码执行因隔离未证明被阻断；产品钩子恢复5/5与真实模型恢复0/1被正确拆开。任务输入中位变化约 +0.108%，用时约 +2.916%，压缩等待大降不等于总体体验大涨；成本为空值，不能给出省钱结论。[S05](../SOURCE-INDEX.md)

## 3. 现在最该修什么

本次执行了8个**原模块组件探针**，不是完整 Pi 集成测试。其中观察到：原宿主导出形状触发加载拒绝；输入图片被拒绝；500-token视图预算下图片可消失；20k字符文本最终仍估算5006 tokens；read首4000字符之后的重要标记不进入首次视图；非循环共享对象被误判为循环；未知扩展块的bypass组合仍会丢块；普通bash里的Maven命令没有进入test-log分类器。具体作用范围和复跑脚本均在[审计](02-current-audit.md)与[证据](../evidence/audit-probes-result.json)中。

这些问题不应该继续靠“给每个 reducer 再补一个白名单”解决。应改成更强的不变量：**原始工具返回默认不变；首次可见不损失；未知类型完整保留；最终渲染才核算预算；无法证明安全就退回 Native。**

## 4. 推荐落地顺序

**里程碑 M1：官方宿主＋只读回读。** 移除补丁依赖，使用公开 hook 和原生 entry；能在全新用户目录中装卸；默认只观察，旧数据不动。

**M2：只对旧观察做稳定周期投影。** 保留最新完整工具批次与必要证据，短任务基本不介入。验证缓存变化和真实模型回读，不把“有指针”当成已恢复。

**M3：原生压缩后的来源胶囊＋Java闭环。** 明确用户约束、未决错误、状态时效、下一步与原始证据引用，模型必须真实运行测试。成功后再推荐 balanced。

**M4：按消融结果决定语义层。** 只有它在相同宿主、模型、任务和总成本口径下，比确定性层有持续净增益，才保留异步摘要、Observer或小型层级索引。否则删除，不把“实现过了”作为留存理由。

## 5. 明确不做的事

不 fork Pi；不模拟 Posthorse 的原生 `context_window`；不在 `turn_end` 再启动独立压缩；不默认改写用户消息、工具参数或图片；不把自动“继续”、多 Agent 调度、Java LSP、跨项目知识库揉进上下文插件；不通过强制截断全部内容维持一个看起来漂亮的token上限。

## 6. 如何判断这条路走对了

先通过零损伤门禁，再证明回读路径被真实模型使用，然后测最终任务。正确问题是：**同样完成 Java 开发任务，错误没有增加，模型回读没有失控，成本／耗时是否下降？** 不是摘要缩短了多少、单个hook有多快、单测有多少个。

交付中给出了完整任务DAG、每任务文件责任和RED/GREEN步骤、故障注入、Java场景、统计口径、发布门禁及删除旧模块的顺序。任何优化未通过证据门禁，仍可保留只读 history 功能，不拖累 Pi 的普通使用。
