# 03 · 历史设计对照、继承与废止

## 资料冲突的根因

仓库docs含多轮完整设计集合和评测材料。一份早期架构不是当前源码的事实；某份后来报告修复了指标，也不意味着更早的架构选择仍须全部保留。v5把“现行约束”“历史解释”“已实现代码”分开，避免多个版本同时指挥Agent。

| 历史集合 | 核心意图 | v5继承 | v5改变或废止 |
|---|---|---|---|
| runtime-greenfield-spec-v1 | host-agnostic kernel、原文先存、可恢复 | 原文与视图区分；来源化引用 | 不再先造跨宿主kernel和第二份完整会话库 |
| compression-benchmark-spec | W1/W2、Native公平对照、reader/closed-loop | 分层实验、相同边界回放、完整成本 | 增加同一官方宿主和真实模型回读硬门禁 |
| runtime-v2-audit-rearchitecture | 修复模块接线、mock与真实路径差异 | 所有核心路径必须过真实宿主 | 不沿用多包层层转发作为正确架构的证明 |
| current-state-audit-next-plan | 真实输出不等于下一请求节省 | 直接测provider输入及最终任务 | 不再使用内部压缩比例推导省钱 |
| deep-audit-v2 | 统一runtime、ACK、恢复与召回 | generation fence、提交确认、可观察失败 | 不将协议receipt扩张为输入接管义务 |
| current-head-remediation-v3 | 真正落地、公平B1/B2、发布证据 | 最小差异实验与完整性检查 | 旧CI红灯、旧丢分母描述不当作当前问题 |
| posthorse-lean-v4 | owner稳定、分支授权前置、默认native、降复杂度 | 单一owner、scope/fence、先确定性后语义 | 500-token首视图不是安全目标；不再要求patched ingress |

完整目录位置、标题、哈希见`evidence/document-catalog.json`，该文件是检索目录，不是“全部精读”的声明。

## 当前实现与历史目标的一致性

已经一致：默认semantic关闭；最新评测不声称公开胜出；分离产品恢复与live recovery；未知价格为空；未证明隔离时不让Agent执行工具；作用域先于结果限制。

仍有结构偏离：强调可作为插件却需要宿主补丁；“bypass未知类型”没有贯穿最终呈现；“预算”可能仅触发切换而非实际限制；已保存证据不代表模型知道何时取回。v5将这些问题从策略参数提升为不可违反的系统契约。

## 没有兼容负担，为什么仍分阶段

不考虑旧API／数据格式兼容，意味着可以停止维护PCR内部接口、旧压缩entry细节、旧CLI别名。它不意味着应该一次性删掉全部验证能力。应先把可观察、可回退的新切片建立起来，再删除旧模块；否则重写会同时丢失功能和判断依据。

新数据命名空间使用`pctx-v5`，不自动读取、迁移或清理旧PCR库。卸载新插件只撤销资源注册。旧代码在版本控制历史保留，旧数据由用户另行决定是否归档。

## 唯一现行规范

合入时把本包作为`docs/evolution-v5/`，根README和AGENTS只链接到它。旧集合统一在`docs/archive/`登记“superseded”。不要求移动所有已有路径以免产生无意义diff；必要时只增加索引说明。新任务每次修改只更新一份对应规范，而不是再复制一整套v5.1目录。
