# 14 · 对照实验、成本与统计计划

## 同一宿主是前提

主实验所有arm固定相同官方Pi版本、Node、工具集、模型快照／路由、推理参数和任务起点。原v4需要patched0.84.4，因此只能作为**历史／诊断lane**，不能与0.85.1新候选的差值全部归因于插件。

| Arm | 组成 | 目的 |
|---|---|---|
| B0 | 官方Pi原生，无插件 | 基准 |
| B1 | history＋observe，无投影／自定义摘要 | 只读恢复能力与固定开销 |
| B2 | B1＋稳定旧观察投影＋native后胶囊 | 主推荐候选 |
| B3 | B2＋experimental-semantic | 语义层消融，不默认启用 |
| D4 | 旧v4＋其patched宿主 | 诊断，不进入主效应估计 |

为保持可解释性，B2的projection-only、capsule-only可另加消融；若没有足够预算，先B0/B1/B2，不同时上线所有变量。

## 两条不同实验轴

**固定前缀回放**：完全相同的native transcript、切点和问题，对比事实保留和读取。适合定位信息损失、分页和回读成本，但不能代替完整代码任务。

**真实闭环**：从相同代码commit和任务启动，模型真实调用工具、修改、测试，允许轨迹自然不同。不能为了“配对公平”强迫两组同一tool trace，那会破坏被测效果。随机交替AB/BA顺序，独立sandbox和provider会话路由，记录cache状态。

## C2恢复专门测试

运行器在工具执行时生成随机不可推导值，值只进入原始tool result；删除生成文件或确保模型无法从普通仓库重建。之后经过真实compaction和足够干扰，要求最终任务使用该值。必须看到**真实模型调用pctx_history并回传正确内容**，再验证下游行为。

C1只证明调用工具能返回它；C2还验证模型会找、找对并用对。若模型猜对但没读取，记录answer-correct但recovery-path-unproven；若值存在固定fixture里被Agentgrep出来，不算恢复。

## 指标定义

任务成功由外部oracle判定，包括编译、测试、用户约束、禁止修改区域、幂等性和最终报告真实性。不能让被测模型或单个LLM judge自报通过。manual review可补充不易自动化的设计质量，但与自动oracle分列。

总成本包含所有主模型调用、缓存读写、输出、辅助摘要、retry/abort已计费部分、history引发的后续推理和重新读文件。保留provider原始usage，再按其字段语义归一化；避免input已经含cached tokens时重复相加。无价格/usage时保留null，输出覆盖率和token指标，不推导货币节省。

总wall time从任务提交到oracle完成；首次冷索引、compaction等待、首token、tool耗时、hook耗时分列。失败和超时仍计入总资源，不能只比较成功任务成本。

## 配对、聚类和缺失

预注册任务族、真实/改编/合成来源、seed、最大执行时长和禁止事项。同一任务换seed不等于新独立任务；主要统计单元是独立task cluster。每个cluster内先按预定规则汇总，再对cluster作bootstrap／成对检验。

计划样本为ITT分母。timeout、隔离失败、provider不可用、artifact缺失单独报告；主质量差可保守将未完成candidate记为失败，但**不可把缺失baseline任意填成功**。完整配对分析与missingness报告同时呈现，不隐藏失败lane。

## 小样本为何不能证明2%非劣

16次都both-pass不意味着质量差精确为0；8个独立cluster的bootstrap可能退化到[0,0]。一个简单保守检查：若n个独立cluster完全没有“baseline过、candidate不过”，该不利事件概率的单侧95%上界为`1 - 0.05^(1/n)`。n=8约31.2%；n=150约1.98%。这仍要求独立、任务分布相关和预先定义最坏cluster结果。

本包统计脚本报告该不利事件上界，**不把它冒充通用净成功率差的置信区间**；candidate胜出可能抵消净差，但不能掩盖关键约束伤害。大规模发布声明应另行采用预注册成对非劣设计和真实独立任务样本。

## 推荐门禁

个人canary：G0–G3全过、无关键约束损伤、8–16个代表任务闭环完成，可标记“本环境有限样本可试用”，不能声明2%NI或普遍胜出。

推荐balanced：足够代表真实场景的预注册样本、完整故障记录、独立oracle；质量下界达到预设非劣目标，且每任务实际成本或耗时相对B1／B0有明确净收益，未优化维度不超过预设退化上限。建议预注册主要资源指标下降≥10%，另一资源维度中位退化≤5%，并分别报告尾部和CI；这些数字是发布政策选择，不是研究发现。

公开“2%非劣”或“广泛优于Native”：需任务分布、样本量与统计方案支持，不能由日常smoke晋升。B3还必须相对B2证明增量价值，否则不发布为默认路径。

## 日常有界smoke

`eval/smoke-plan.json`给出可选约55分钟墙钟上限：8个任务、B0/B2、每arm最多180秒，外加预热与汇总；达到总预算时剩余项incomplete。它是预算配置，不保证本地27B能完成所有任务。构建镜像、安装依赖和大样本非劣试验不属于该时间预算。

实际运行器由T20–T23实现；本包只提供计划、样本协议、统计工具和部分可独立执行的Java oracle素材，**不伪造一条已经存在的one-command live runner**。
