## RED：先写可失败的行为测试

引入contracts/model.ts与config.schema.json对应类型；未知配置字段和伪造ref应被拒绝。

1. schemaVersion不是5时不能启用balanced。
2. telemetry.includeContent=true必须拒绝。
3. fixture工厂能生成独立branch、图片、完整/缺失batch、失败请求，不隐含“总是成功”的宿主。

先确认测试因目标行为尚未实现而失败，而不是文件拼错、测试没有被发现或依赖缺失。基础模块缺失时先放最小可编译接口，再观察断言RED，不把import错误当功能测试证据。

## GREEN：最小实施步骤

1. 建立公开内部类型和严格运行时校验，集中错误码。
2. 编写最小native-shaped fixture工厂，并明确没有真实host的测试等级。
3. 创建各test目录和基础命令，不允许空测试集exit0被当作通过。

完成后删除本任务内部重复状态和冗余转发，不增加不在任务范围内的策略。修改契约需要同步更新受影响任务与测试，不能用类型断言绕过。
