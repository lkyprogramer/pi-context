## RED：先写可失败的行为测试

读取已接纳用户消息与工具结果，使用原生entry id/parentId；不注册input接管。

1. 图片input经过实际Pi后仍在native记录和下次provider输入。
2. 同文本不同entry不合并；toolCallId碰撞且hash不同应映射歧义。
3. message_end持久化顺序变化后，下一context能补齐或安全bypass。

先确认测试因目标行为尚未实现而失败，而不是文件拼错、测试没有被发现或依赖缺失。基础模块缺失时先放最小可编译接口，再观察断言RED，不把import错误当功能测试证据。

## GREEN：最小实施步骤

1. 实现readVisibleSnapshot与增量getLeaf/getEntry游标。
2. 按可见branch有序映射出站消息；唯一toolCallId仍须hash校验。
3. 将hook接线与策略分离，所有失败默认不修改消息。

完成后删除本任务内部重复状态和冗余转发，不增加不在任务范围内的策略。修改契约需要同步更新受影响任务与测试，不能用类型断言绕过。
