# 给执行Agent的唯一入口

## 任务

把目标仓库重构为官方Pi可安装的native-first上下文插件，遵循`docs/05…18`、`contracts/`和`tasks/`。不要求兼容旧PCR格式与API，但不得删除用户数据、改动全局Pi或破坏未提交代码。

## 先做

核对当前git状态、真实Node/Pi版本、依赖锁文件与本包冻结head差异。若仓库已推进，先列出差异并判断本次源码缺陷是否已修复，不机械复写。为工作创建隔离分支/worktree，读取项目当前AGENTS规范；发生冲突以用户要求及公开宿主约束为准。

运行本包`python3 scripts/validate_bundle.py`仅确认设计包完整。随后在目标仓库按T01/T02建立真实测试基础设施。**该校验脚本不等于插件测试通过。**

## 不可违反的约束

官方Pi拥有会话/输入/分支/压缩/重试；插件不依赖PCR补丁、不拦截图片输入、不改原始tool_result、不改工具参数、不触发无限续跑。未知内容完整保留。授权先于检索排序/limit。所有有损投影须能找到真实来源，首次暴露完整。

没有真实host／provider／沙箱时，能够完成静态实现和单元测试，但必须将相应集成、C2、E2E标成NOT-RUN/BLOCKED。不得用“应该通过”覆盖验证空白，不得生成虚构benchmark数字。

## 执行协议

从`tasks/task-graph.json`选择所有依赖已验收的任务。每个任务：读取规范→写RED行为测试→确认失败原因→最小实现→GREEN→受影响回归→只读review→保存证据。未通过的任务不能解锁下游。公共接口由协调者维护，文件写入责任按任务卡执行。

测试报错先追踪真实数据流和作用范围，禁止同时改多个无关模块“试试”。优化失效时退回native，不用更激进截断消除错误。

## review提示词

“只读审查当前任务diff、公开Pi契约和真实测试日志。找出first-exposure、图片、branch scope、source hash、ACK、cache和费用统计的违反项。区分代码证据、stub测试、真实host与实际模型。不给实现者自报的pass背书。返回必须修改项、证据位置和对应回归测试；不要扩展任务范围。”

## 发布限制

保持private:true。未经用户明确授权不得npm publish、push main、创建Release、上传原文session或生产数据。先完成T26发布候选审查并报告推荐级别；语义层可不进入核心发布。

## 结束交付

交付源码commit、tarball/hash、固定官方宿主身份、G0–G5证据表、实测结果和未覆盖范围，以及一条经过实际验证的安装命令。没有端到端数据时只交付实现候选，不写“最佳效果已验证”。
