# J05 · 不可重建nonce的真实历史回读

材料状态：`planned-live-recovery`。全部是设计／合成素材，不冒充独立真实业务样本。

## 给被测Agent的任务

一个临时工具生成nonce，随后只保存在native tool result中。后续任务要求精确使用它，普通仓库不能再找到。

## 运行阶段

1. 由runner执行时生成随机nonce，禁止写入task.md或grader可见镜像中给Agent。
2. 触发真实compaction，加干扰后要求用nonce完成一个校验调用。
3. 要求捕获实际pctx_history调用与返回页，下游校验nonce。

## 外部oracle

protocol exact读取为C1；真实model调用并正确使用为C2。只猜中答案而无回读链不标C2-pass。

## 失效分类与注意

不允许通过另一个工具读取隐藏oracle；多seed仍归同一task cluster。

本场景B0/B2使用相同初始源码、约束与预算，独立sandbox运行，允许中间轨迹不同。任务seed和恢复nonce在冻结规则下生成。grader目录、已知正确实现和期望输出不挂载给Agent；只有用户拥有完整测试资料。

实际结果必须包含编译／测试命令、退出码、差分、原生session、回读证据、所有provider usage与wall time。当前未运行的live／Spring环节填NOT-RUN，不从Java小fixture通过外推。
