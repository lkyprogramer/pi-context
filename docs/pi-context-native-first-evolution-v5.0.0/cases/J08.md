# J08 · 连续压缩后保持旧接口契约

材料状态：`planned-java-migration`。全部是设计／合成素材，不冒充独立真实业务样本。

## 给被测Agent的任务

迁移多个Java入口，保留原HTTP路径、方法、参数与响应；禁止跨schema写，允许内部重构，不涉及生产支付。

## 运行阶段

1. 执行至少两个阶段和两次自然或可控压缩，记录独立任务计划。
2. 中途注入一个失败回归与session reload，继续未完成工作。
3. 最后做契约差分、数据库副作用与全套选定测试。

## 外部oracle

外部固定契约快照、禁止文件修改检查、实际测试退出码和重复执行副作用检查；不能只检查文档里列了所有路径。

## 失效分类与注意

两次压缩只测压力场景，不据此宣称能无限长时间保持语义无损。

本场景B0/B2使用相同初始源码、约束与预算，独立sandbox运行，允许中间轨迹不同。任务seed和恢复nonce在冻结规则下生成。grader目录、已知正确实现和期望输出不挂载给Agent；只有用户拥有完整测试资料。

实际结果必须包含编译／测试命令、退出码、差分、原生session、回读证据、所有provider usage与wall time。当前未运行的live／Spring环节填NOT-RUN，不从Java小fixture通过外推。
