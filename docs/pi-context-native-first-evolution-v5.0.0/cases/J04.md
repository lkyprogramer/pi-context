# J04 · 长Maven日志中的首个因果错误

材料状态：`planned-maven`。全部是设计／合成素材，不冒充独立真实业务样本。

## 给被测Agent的任务

日志有大量warning和重复下载行；真正失败行位于首4000字符之后。不能只依据最终BUILD FAILURE文本猜原因。

## 运行阶段

1. 运行真实失败构建，插入非关键干扰行；关键error位置按seed变化。
2. 第一轮必须看到完整宿主保存的结果；后续可压缩旧噪声。
3. 跨压缩继续修复真实根因并运行相同构建。

## 外部oracle

检查根因对应源码更改及完整Maven退出码；确保未修改pom跳过相关测试。分别检测首次观察丢失与历史恢复失败。

## 失效分类与注意

优先使用真实编译错误，不把预写的BUILD SUCCESS当oracle。

本场景B0/B2使用相同初始源码、约束与预算，独立sandbox运行，允许中间轨迹不同。任务seed和恢复nonce在冻结规则下生成。grader目录、已知正确实现和期望输出不挂载给Agent；只有用户拥有完整测试资料。

实际结果必须包含编译／测试命令、退出码、差分、原生session、回读证据、所有provider usage与wall time。当前未运行的live／Spring环节填NOT-RUN，不从Java小fixture通过外推。
