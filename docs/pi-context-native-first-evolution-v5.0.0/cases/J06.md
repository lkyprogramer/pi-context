# J06 · 分支约束冲突与pin生命周期

材料状态：`planned-host-live`。全部是设计／合成素材，不冒充独立真实业务样本。

## 给被测Agent的任务

祖先约束禁止跨schema写；分支A探索放宽、分支B保留原限制。B不能看到A私有建议，也不能继承A的unpin。

## 运行阶段

1. 建立原生branch与pin，在A生成高关键词匹配诱饵。
2. 回B后搜索并压缩，验证祖先可见性。
3. 继续Java/SQL修改，确保未采用A的建议。

## 外部oracle

host断言返回ref全部属于B祖先；最终diff与SQLoracle检查无跨schema写。两层都要通过。

## 失效分类与注意

scope hash正确但模型从其他注入文本看到A仍为端到端泄漏失败。

本场景B0/B2使用相同初始源码、约束与预算，独立sandbox运行，允许中间轨迹不同。任务seed和恢复nonce在冻结规则下生成。grader目录、已知正确实现和期望输出不挂载给Agent；只有用户拥有完整测试资料。

实际结果必须包含编译／测试命令、退出码、差分、原生session、回读证据、所有provider usage与wall time。当前未运行的live／Spring环节填NOT-RUN，不从Java小fixture通过外推。
