# Retrieval and recovery behavior

`context_read` returns a bounded UTF-8 page instead of implicitly returning an entire blob. Existing `evidenceId`, `sha256`, `verified`, `byteLength`, `range`, and `text` fields remain. `sha256` identifies the original blob, not just the page. `nextOffset` is the next **byte** offset (or `null` when the requested range is complete); pass it as `start` to continue. `remainingBytes` counts bytes left within the requested range. `endExclusive` remains an optional upper byte boundary, and `maxTokens` can request a smaller response.

The serialized response, including JSON escaping and metadata, is capped at 4,096 UTF-8 bytes. Its budget also reserves the model's maximum output and 1,024 continuation tokens, then uses at most half of the remaining estimated capacity. A byte per token is a conservative sizing rule, not a provider tokenizer measurement. Unknown usage also reconstructs the current native messages (including the retained tail and summary) using Pi’s public API, then adds prompt and tool-schema estimates. With no model context, the fixed cap still applies. Insufficient capacity raises `PCR_RETRIEVAL_BUDGET_EXCEEDED` with the retry offset; compact before retrying. Automatic page boundaries preserve UTF-8 code points. Exact explicit byte ranges retain their existing byte semantics.

`context_recall` retains its plain-text output and UTF-16 **character** offsets (`start` / `end`). It applies the same live budget, keeps the existing default 256-token request cap, and includes a continuation instruction when truncated. Neither tool reduces encryption integrity checks: the authenticated blob is still read and verified in full before a page is selected. This change bounds model output, not peak decryption memory.

PCR's own `context_read`, `context_recall`, and `context_search` results pass through `tool_result` unchanged. They have already resolved scoped originals and must not be converted into another observation pointer or indexed as fresh evidence. Other tool results retain their existing capture and projection path.

Each SQLite FTS index caches only its most recent query. The key includes the complete cursor, query, limit, SQLite `data_version`, and `total_changes()`. Same-connection and other-connection writes invalidate reuse; returned results cannot mutate the cache. This optimizes unchanged repeated searches, not state-changing materialization or all database reads.

Compaction no longer captures `messagesToSummarize` text as new authenticated user input. Before preparing a checkpoint, it reconstructs the complete directive projection from current-branch native user entries with valid linked PCR ingress receipts, verified source hashes, and authenticated-user provenance. It reads original encrypted input under its original cursor and atomically writes only the current-cursor directive/claim projection, without another ledger receipt. Cross-cursor source identities are scoped to the target cursor to avoid global ID collisions. A partially populated projection never counts as a completed recovery. Assistant/tool text, extension-origin input, and legacy entries without receipt provenance cannot be promoted. When required directives cannot be recovered, the existing native fallback remains in control.

Production retrieval ceilings now come from `@pcr/core`. Legacy kernel exports remain for existing W1 consumers. Legacy backup/GC/key-rotation wiring is unchanged: those operations need a separate V2 data-contract migration, not a facade rename.
